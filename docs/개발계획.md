# RansomUtilFactory 개발 계획

## 1. 목표와 기본 원칙

RansomUtilFactory는 Windows에서 랜섬웨어의 파일 접근 및 대량 변경 행위를 감시하고,
정책에 따라 접근을 제한하는 방어 프로그램이다. 커널 드라이버는 최소한의 수집과
강제 기능만 담당하고, 정책 관리와 사용자 인터페이스는 사용자 모드 구성 요소가
담당한다.

개발 순서는 파일시스템 미니필터, 파일 통신 DLL, 개발용 WPF UI, 프로세스 드라이버,
프로세스 통신 DLL, 통합 및 배포 준비 순서로 고정한다.

## 2. 단계별 구현 계획

### 2.1 `UF_FileFilterFactory`

책임:

- 다수의 감시 폴더와 접근 제한 폴더 정책을 유지한다.
- 감시 폴더 접근 시 프로세스와 파일 정보를 사용자 모드로 전달한다.
- 감시 예외 프로그램의 접근은 알리지 않는다.
- 접근 제한 폴더는 허용 프로그램 이외의 사용자 모드 접근을 차단한다.
- 보호 폴더마다 허용 프로세스와 읽기·쓰기 권한을 독립적으로 지정한다.
- 허용 프로세스마다 코드 서명 확인 여부를 선택한다. 확인하는 경우 전체 이미지 경로와
  유효한 코드 서명으로 함께 식별하고, 확인하지 않는 경우 전체 이미지 경로만 식별한다.
- PID와 프로세스 생성 식별자를 함께 검사하여 PID 재사용을 막는다.
- 커널 기원 입출력, 페이징 파일 및 지원하지 않는 볼륨을 안전하게 제외한다.

구현 순서:

1. 현재 `IRP_MJ_CREATE` 기반 감시와 차단 기능을 안정화한다.
2. 정책의 경로 및 프로세스 이미지 문자열 검증을 강화한다.
3. 보호 프로세스별 읽기·쓰기 권한과 인증서 식별자를 정책 ABI에 추가한다.
4. 쓰기, 이름 변경, 삭제 및 섹션 매핑 이벤트 범위를 추가한다.
5. 이벤트 유실·시간 초과·연결 해제를 계측하고 차단 경로에서 장시간 대기하지 않도록 한다.
6. 배포 전에 Microsoft에서 정식 미니필터 고도 값을 배정받아 INF에 적용한다.

완료 조건:

- x64 Debug 및 Release 빌드가 경고 없이 성공한다.
- 정책 교체, 초기화, 조회, 감시 예외 및 허용 목록 차단 시험이 통과한다.
- 잘못된 메시지 크기·버전·개수·문자열 길이 입력을 거부한다.
- 서명 확인을 선택한 규칙은 서명되지 않았거나 허용된 서명자와 일치하지 않으면 차단한다.
- 서명 확인을 끈 규칙은 경로가 교체될 수 있다는 경고를 표시하고 명시적으로 선택한 경우에만 적용한다.
- 정책 교체, 프로세스 종료·재시작, PID 재사용 및 인증서 폐기 무효화 시험이 통과한다.
- 사용자 모드 클라이언트가 없거나 중단되어도 시스템 입출력이 교착되지 않는다.
- Driver Verifier와 파일시스템 필터 관련 시험에서 충돌과 메모리 누수가 없다.

### 2.2 `uf_fltwarp`

책임:

- `UF_FileFilterFactory` 통신 포트 연결을 관리한다.
- WPF 프로그램에서 사용할 C ABI 함수를 제공한다.
- DOS 경로를 정규화된 NT 장치 경로로 변환한다.
- 정책 설정, 초기화, 상태 조회 및 비동기 파일 이벤트 수신을 담당한다.

공개 함수 범주:

- 라이브러리 초기화와 종료
- 드라이버 연결과 연결 해제
- 전체 정책 원자적 교체와 정책 초기화
- 드라이버 상태 조회
- 이벤트 수신 시작·중지 및 C 호출 규약 콜백 등록
- 오류 코드를 사람이 읽을 수 있는 한국어 메시지로 변환

완료 조건:

- C와 C# P/Invoke 시험 프로그램에서 동일한 ABI로 호출된다.
- 반복 연결·해제, 드라이버 재시작 및 UI 비정상 종료 후 재연결이 가능하다.
- 이벤트 수신 스레드 종료 시 대기 중인 요청이 안전하게 취소된다.
- 잘못된 경로와 허용 개수 초과 입력이 드라이버 전송 전에 거부된다.

현재 구현 상태:

- C ABI 공개 헤더와 연결·정책·상태·이벤트 수신 함수를 구현했다.
- 로컬 DOS 경로를 NT 장치 경로로 변환하는 기능을 구현했다.
- C 기반 `UF_FileFilterTest`로 경로 변환과 드라이버 통신을 시험할 수 있다.
- 실제 드라이버 연결·정책·이벤트 통합 시험은 시험 서명 VM에서 수행해야 한다.
- V2 보호 정책, 서명자 식별 및 프로세스 신뢰 갱신 API를 구현했다.

### 2.3 개발용 WPF UI

책임:

- 감시 폴더, 접근 제한 폴더, 감시 예외 프로그램 및 허용 프로그램을 편집한다.
- DLL을 통해 정책을 드라이버에 적용하고 현재 상태를 표시한다.
- 파일 접근과 차단 이벤트를 실시간 목록과 로그로 제공한다.

완료 조건:

- 관리자 권한과 드라이버 연결 상태를 명확히 표시한다.
- 입력 중인 정책과 드라이버에 적용된 정책을 구분한다.
- 중복·포함 관계가 있는 경로와 존재하지 않는 실행 파일을 검증한다.
- 이벤트 폭주 시 UI가 멈추지 않으며 표시 개수와 로그 크기에 상한이 있다.

현재 구현 상태:

- `파일 제어`와 `프로세스 제어` 탭을 구성했으며 프로세스 제어는 안내 화면만 제공한다.
- 파일 제어에서 감시 폴더와 보호 폴더를 여러 개 추가·제거하고 정책을 적용할 수 있다.
- 감시 및 차단 이벤트를 최대 2,000개까지 실시간 로그로 표시한다.
- 동일 경로의 감시·보호 중복을 거부하고 하위 경로 규칙을 먼저 전송한다.
- 보호 폴더별 허용 실행 파일을 추가·제거하고 실행 파일마다 읽기·쓰기 권한과 코드 서명
  확인 여부를 설정한다.
- 서명 확인을 선택한 허용 실행 파일만 정책 적용 전에 로컬 코드 서명을 확인하고 인증서
  SHA-256 지문 기반 V2 보호 정책으로 전송한다.
- 서명 확인을 끈 허용 실행 파일은 서명자 규칙 없이 경로 기반 V2 보호 정책으로 전송한다.
- 감시 예외 프로그램 편집은 후속 단계에서 구현한다.
- 파일 제어 탭에서 파일 미니필터 설치·로드와 언로드·제거를 수행할 수 있다.
- 프로세스 제어 탭의 설치·제거 버튼은 프로세스 드라이버 구현 전까지 비활성화한다.
- DLL, C 시험 프로그램 및 WPF UI는 구성요소별 로그 파일을 `logs` 폴더에 기록한다.
- 네이티브 DLL 로그도 DLL 파일 위치가 아니라 호스트 UI·시험 프로그램의 실행 위치를
  기준으로 기록하여 동일한 실행 폴더에서 진단할 수 있게 한다.
- 네이티브 초기화가 중단되는 경우 `uf_fltwarp.bootstrap.log`로 로그 초기화 전후
  단계를 확인할 수 있게 한다.
- 네이티브 DLL은 정적 `log4cpp` 라이브러리를 빌드·연결하되 UI 초기화 경로에서는
  Win32 파일 기록을 기본으로 사용하여 로깅 실패가 UI 종료로 이어지지 않게 한다.
- 로그에는 연결, 정책 적용, 이벤트 수신, 설치·로드 오류와 UI 예외를 기록하되
  파일 내용이나 자격 증명은 기록하지 않는다.

### 2.4 `UF_ProcessFilterFactory`

책임:

- 프로세스 생성·종료 정보를 수집한다.
- 정책에 필요한 프로세스 식별 정보와 부모 관계를 사용자 모드로 전달한다.
- 방어 정책에 필요한 최소 범위에서 프로세스 생성 제한을 지원한다.

완료 조건:

- 프로세스 생성·종료 이벤트의 PID 재사용과 순서를 올바르게 처리한다.
- 필수 Windows 프로세스와 커널 기원 동작을 안전하게 취급한다.
- 콜백 등록 해제와 드라이버 언로드 중 경쟁 상태가 없다.
- Driver Verifier 실행에서 충돌과 누수가 없다.

### 2.5 `uf_procwarp`

책임:

- `UF_ProcessFilterFactory`와의 연결과 정책 통신을 관리한다.
- C ABI로 프로세스 정책 및 이벤트 함수를 공개한다.
- WPF UI에 프로세스 수명 주기와 정책 적용 결과를 전달한다.

완료 조건:

- C 및 C# P/Invoke 호환성 시험을 통과한다.
- 드라이버 재시작과 통신 장애 후 재연결이 가능하다.
- 파일 이벤트와 프로세스 이벤트를 PID와 생성 시각 기준으로 연관 지을 수 있다.

## 3. 통합 시험

- 정상 프로그램, 허용 프로그램 및 감시 예외 프로그램의 파일 접근을 비교한다.
- 비허용 프로그램의 읽기·쓰기·이름 변경·삭제 및 메모리 매핑 접근을 시험한다.
- 대량 파일 생성과 변경 상황에서 이벤트 처리량, 유실 수, CPU 및 비페이징 풀 사용량을 측정한다.
- DLL, UI 또는 드라이버를 임의 순서로 시작·중지해 연결 복구와 정책 상태를 확인한다.
- 정책 적용 도중 동시 파일 접근을 발생시켜 부분 적용이 없는지 확인한다.
- 로컬 NTFS, 이동식 저장장치 및 지원 대상 파일시스템별 동작을 기록한다.
- 시험 서명된 전용 VM에서 Driver Verifier와 WinDbg를 사용해 장애를 분석한다.

## 4. 배포 준비

- 정식 미니필터 고도 값과 드라이버 서명 절차를 확정한다.
- INF, 카탈로그, 드라이버, 네이티브 DLL 및 WPF 프로그램의 버전을 일치시킨다.
- 설치, 업그레이드, 롤백 및 제거 절차를 자동화하고 재부팅 필요 조건을 문서화한다.
- 기본 정책은 시스템을 사용할 수 없게 만들지 않는 보수적인 설정으로 제공한다.
- 진단 로그에 민감한 전체 파일 내용이나 자격 증명을 기록하지 않는다.
- HLK 및 제품 지원 대상 Windows 버전별 회귀 시험 결과를 보관한다.
