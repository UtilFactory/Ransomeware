# 부팅 영역 보호 2차 버전 계획

결정일: 2026-09-14 · 브랜치: `tsk/8/main`

상태: 사용자와 합의한 후속 계획이며 아직 구현하지 않았다. 현재 배포는 파일 미니필터
기반 1차 버전을 유지한다. 이 문서의 2차 버전은 개발 단계 이름이며 통신 ABI 버전이 아니다.

## 1. 우선순위와 결정

- 긴급한 1차 기능을 먼저 마무리한다. 현재 파일 필터에서 보호 시작·정지, 실제 변경 쓰기
  차단, UI 차단 로그와 요청 프로세스 경로 표시를 VM에서 확인하고 발생 오류를 수정한다.
- 지적된 보호 범위·검사 실패·직접 디스크 I/O 공백은 디스크/스토리지 필터 드라이버를
  사용하는 2차 구조에서 보완한다. 지금 별도 디스크 드라이버나 디스크 탭을 복원하지 않는다.
- 1차의 제한 사항을 해결 완료로 표시하지 않는다. 현재 구현과 검증 결과는
  [1차 구현 문서](파일필터_부트보호_구현.md)를 따른다.

## 2. 2차 목표와 구조

- 최종 목표는 가상 머신과 물리 머신의 현재 C: 시스템 볼륨에 관련된 부팅 영역 보호다.
  C:와 대응 물리 디스크·실제 부팅 파티션의 관계를 확인하며, 서로 같은 디스크에 있다고
  가정하지 않는다. 지원 장치 구성과 검증되지 않은 구성은 구분한다.
- 디스크/스토리지 계층에서 보호 구간의 무허가 쓰기를 하위 계층으로 전달하기 전에
  차단하는 구조로 전환한다. KMDF 디스크 상위 필터를 우선 검토하되, 물리 디스크 핸들과
  볼륨 핸들 요청이 실제로 도달하는지 검증한 뒤 부착 위치와 지원 범위를 확정한다.
- 파일 미니필터는 폴더·파일 접근 정책을 유지한다. 부팅 영역 차단의 책임을 분리하고,
  전환 중 이중 차단이나 중복 로그가 생기지 않도록 1차 기능의 비활성화 절차를 설계한다.
- 보관 중인 `UF_BootProtectionFactory`와 `uf_bootwarp`는 재검토할 기반일 뿐이다.
  이전 구현을 그대로 켜는 것으로 C: 보호가 완성되었다고 보지 않는다. 이전 구현의
  VHDX 전용 제한과 OS 디스크 제외 조건은 2차 최종 목표가 아니다.
- VHDX는 안전한 시험 수단으로만 활용하며, 2차 제품 보호 대상을 VHDX로 제한하지 않는다.

## 3. 필수 보완 항목

1. 보호 구간을 고정 선두 2 KiB에서 검증된 디스크·파티션 배치에 따른 구간으로 확장한다.
   MBR, GPT 기본/백업 헤더와 엔트리 배열, FAT32·NTFS 기본/백업 부팅 영역을 대상으로
   범위 계산·겹침·섹터 크기·정수 경계를 검증한다. EFI 파일/BCD 보호는 별도 파일 정책이다.
2. 매 쓰기마다 장치를 다시 열어 기존 내용을 비교하는 의존성을 줄이고, 검증해 보관한
   보호 구간과 명시적 허용 정책으로 판정한다. 잠긴 볼륨·공유 제한·읽기 실패 때문에
   보호 쓰기가 자동 통과하는 현재 공백을 보완한다.
3. 초기 장치 식별 실패, 활성 상태의 판정 실패, 장치 제거·레이아웃 변경을 구분한다.
   보호 활성 상태의 확인된 보호 구간에 대한 무허가 쓰기는 차단하는 것을 목표로 한다.
   보호 범위를 확인하지 못했는데 활성으로 표시하거나 모든 OS 쓰기를 무조건 막지 않는다.
   구체적인 실패 처리와 복구 절차는 2차 설계에서 확정하고 시험한다.
4. 대용량·동시 쓰기 및 자원 부족 때 발생하는 보호 공백, 저장장치 지연에 따른 대기와
   언로드 수명 문제를 보완한다. 직접 디스크 I/O와 저장 내용을 변경하는 제어 경로를
   조사하고, 관찰·차단 여부를 요청 종류별로 시험한다. 미검증 경로까지 지원한다고 하지 않는다.
5. 정상 Windows 업데이트·부팅 복구·디스크 관리 작업을 위한 제한된 유지보수 허용을
   설계한다. SYSTEM 또는 서명 여부만으로 일괄 예외 처리하지 않고 장치·영역·작업·기간을
   제한하며, 만료와 철회 및 정상 OS 호환성을 검증한다.
6. UI의 시작·정지·실제 상태 조회와 오류 코드·차단 로그·PID·생성 식별자·이미지 경로
   표시를 유지한다. 커널의 차단 결정은 사용자 모드 응답이나 경로 조회 완료를 기다리지
   않게 설계하며, 정보 미확인·이벤트 유실을 표시한다. UI 탭 배치와 통신 ABI는 별도 확정한다.

자동 프로세스 종료·격리·파일 삭제는 이번 구조 전환 결정만으로 완료되거나 착수한 것으로
보지 않는다. 필요 시 별도 범위와 프로세스·파일 동일성 검증 절차를 정한다.

## 4. 착수 및 완료 기준

- 1차 VM 동작 확인과 긴급 오류 수정을 우선하고, 이후 사용자와 2차 착수 시점을 정한다.
- 먼저 부착·설치·복구 절차와 지원 디스크 구성, 보호 범위·예외·실패 정책을 설계한다.
  ABI 변경이 필요하면 코드 수정 전에 [통신 규약](통신규약.md)에 호환성을 기록한다.
- 합성 구간 시험과 폐기 가능한 시험 디스크에서 판정·I/O 경로를 확인한 뒤, 검사점과
  복구 절차가 준비된 Windows VM에서 시스템 디스크 보호와 정상 부팅·재부팅을 검증한다.
  물리 머신 지원은 목표이며 개발 장비나 운영 C:에서 파괴 시험을 수행한다는 뜻이 아니다.
- 시작·정지, 잠금/공유 제한, 요청 경계, 대량 쓰기, 자원 부족, 클라이언트 종료,
  장치/드라이버 수명·PnP·전원·취소, 업데이트·복구·유지보수 및 Driver Verifier 검증을 기록한다.
- 차단 요청의 실패 코드와 로그만으로 성공을 판단하지 않고, 시험 전후 보호 구간의
  내용·해시가 유지되는지 확인하여 실제 쓰기 차단을 검증한다.
- 전체 Debug/Release x64 빌드와 패키지 검사, 실제 커널 차단·UI 사건 표시 및 회귀 시험을
  구분하여 보고한다. 검증하지 않은 장치·I/O 경로를 보호 완료로 표시하지 않는다.

이번 기록에서는 코드·프로젝트·드라이버·UI·설치 상태를 변경하지 않았다.
[이전 설계안](부팅영역보호_설계안.md)은 과거 검토 기록이며, 2차 우선순위와 목표는 이 문서를 따른다.
