# 부팅 영역 보호: 1차 구현과 사용법

작성일: 2026-09-14 · 작업 브랜치: `tsk/8/main`

## 현행 사용법: 파일 미니필터 이관

별도 디스크 드라이버와 DLL, 디스크 탭은 사용하지 않는다. 파일 필터와 `uf_fltwarp.dll`,
UI를 함께 교체한다. 관리자는 검사점이 있는 Win11 시험 VM에서 파일 필터를 설치·연결한 후
`파일 제어` 탭의 MBR/GPT 선두 영역 보호에서 시작·정지·상태 조회를 수행한다.

- 연결은 통신 상태이며 보호 시작이 아니다. 시작 성공 후 실제 상태 조회까지 확인한다.
- 정지는 이 보호만 해제하며 폴더 정책은 유지한다. 폴더 정책 초기화도 이 보호를 끄지 않는다.
- 연결 해제·UI 종료 시 이미 활성화한 보호는 유지한다. 조회 실패는 정지가 아니라 미확인이다.
- 기존 파일 로그의 `부트 영역 차단`은 내용 변경 차단, `부트 검사 실패(통과)`는 비교 불가로
  통과시킨 사건이다. 요청 PID·프로세스 경로·대상 장치를 확인한다.
- 원본과 같은 선두 2048바이트 비교이다. VHDX만 대상으로 하지 않지만 C: 볼륨 접근과
  물리 디스크 접근의 경로 차이 및 GPT 전체·백업 보호 완료를 혼동하지 않는다.
- 이전 드라이버가 이미 설치된 VM에서는 자동으로 제거하지 않는다. 해당 시험 디스크의
  필터 등록 해제와 재부팅 여부를 확인한 뒤 이관본만으로 시험하여 이중 차단을 피한다.
  디스크 클래스 전체의 UpperFilters를 삭제하는 방식으로 정리하지 않는다.

콘솔도 같은 파일 통신 DLL을 사용한다. UI와 CLI는 하나의 포트를 동시에 점유하지 않는다.

```powershell
.\x64\Debug\bin\UF_FileFilterTest.exe --boot-self-test
# 아래 명령은 파일 드라이버가 설치된 시험 VM에서 실행한다.
.\x64\Debug\bin\UF_FileFilterTest.exe --boot-state
.\x64\Debug\bin\UF_FileFilterTest.exe --boot-start
.\x64\Debug\bin\UF_FileFilterTest.exe --boot-stop
```

기능별 구현 위치·보완 사항·최신 검증 결과는 [구현 기록](파일필터_부트보호_구현.md)을 따른다.

## 이전 별도 디스크 드라이버의 구현 기록 (현행 사용 금지)

아래는 이전 커밋의 시험 기록을 보존한 것이다. 디스크 탭과 `--vhdx-protection-test`는
현행에서 제거/중단했으므로 아래 설치·실행 절차를 현행 사용법으로 적용하지 않는다.

## 1. 이번에 추가한 기능

기존 프로세스 콜백이나 파일 미니필터가 아니라 **별도 KMDF 디스크 상위 필터**
`UF_BootProtectionFactory.sys`가 보호 구간과 겹치는 디스크 쓰기를 하위 장치에 전달하기
전에 거부한다. `uf_bootwarp.dll`과 WPF `부트 영역 방어` 탭에서 디스크별로 방어를
시작·정지하고 상태와 차단 로그를 확인한다. 파일·프로세스 드라이버 ABI는 그대로다.

초기 대상은 **Hyper-V 게스트 안에서 프로그램이 새로 생성·연결한 시험용 데이터 VHDX**다.
OS 디스크·EFI/MSR/복구 파티션·동적 디스크·Storage Spaces·기타 버스는 지원하지 않는다.
호스트에서 VM에 추가한 가상 SCSI 디스크와 게스트 내부의 `FileBackedVirtual` VHDX는
구분된다. 목록에 없다고 디스크 클래스 전체에 필터를 강제 등록하지 않는다.

연결이나 설치만으로 차단을 켜지 않는다. 초기·재부팅·디스크 재부착 상태는 `정지`다.
UI의 **`부트 영역 방어 시작`**이 성공하고 커널 상태가 **`방어 중`**이어야 활성이다.
UI 종료·통신 실패는 자동 정지가 아니다. **`부트 영역 방어 정지`**가 실제 차단을 해제한다.

## 2. 구성과 보호 범위

| 구성 | 역할 |
| --- | --- |
| `UF_BootProtectionFactory` | KMDF PnP 디스크 상위 필터, 배치 검증, 쓰기/제어 요청 차단, 상태·이벤트 |
| `uf_bootwarp` | 독립 핸들 기반 QUERY/SET/EVENTS, 제한 시간·입출력 ABI 검사·Win32 오류 |
| `RansomUtilFactory.UI` | 안전한 시험 디스크 선택·등록, 방어 시작·정지, 커널 상태·로그 |
| `UF_BootProtectionTest` | 합성 검사와 신규 폐기용 VHDX에서 방어 켬/끔 실제 쓰기 비교 |

커널은 섹터 크기 512/4096바이트, 실제 디스크 길이, MBR/GPT 및 기본·백업 BPB를
교차 검사한다. GPT 기본/백업 헤더 CRC와 파티션 엔트리 CRC·내용도 확인한다.
지원하지 않거나 모순된 배치는 시작 실패로 남기고 보호 활성이라고 표시하지 않는다.

- MBR: 디스크 첫 논리 섹터. 활성 부팅 파티션과 확장·비지원 파티션은 시작 대상에서 제외한다.
- GPT: 보호 MBR, 기본·백업 GPT 헤더와 파티션 엔트리. 기본 데이터 파티션만 지원한다.
- NTFS: 파티션 처음 16개 논리 섹터와 마지막 백업 부트 섹터.
- FAT32: 지원하는 표준 배치의 기본 부트·확장 부트 섹터와 백업본. 정상 FSInfo 갱신 영역은
  차단 구간에서 제외한다. 정확한 실제 오프셋·길이는 시작 후 UI의 보호 범위 목록에 표시한다.

활성 상태에서는 겹치는 전체 쓰기를 `STATUS_ACCESS_DENIED`로 거부한다. 알 수 없는
변경 가능 IOCTL, 레이아웃 변경, TRIM 및 전달 명령도 보수적으로 거부한다. 조회로 분류한
명령과 범위 밖 일반 쓰기는 전달한다. 쓰기 본문으로 랜섬웨어를 판별하거나 SYSTEM·서명만으로
예외 허용하지 않는다. 초기에 범용 스토리지 호환성을 보장하는 정책이 아니므로 실사용 금지다.

## 3. VM 설치와 UI 버튼

1. **Win11 VM 검사점**을 만들고 시험 서명·인증서 신뢰를 준비한다. 호스트에는 설치하지 않는다.
2. 전체 빌드한 `x64\Debug\bin`을 통째로 VM의 로컬 폴더에 복사한다. SYS/INF/CAT/DLL/UI를
   서로 다른 빌드에서 섞지 않는다. 신규 `UF_BootProtectionFactory.cer`도 필요하다.
3. 관리자 권한으로 UI를 실행하고 `부트 영역 방어` 탭에서 설치·필터 등록 영역을 펼친 뒤
   `드라이버 패키지 설치`를 누른다.
   이 버튼은 인증서를 임의 신뢰하거나 디스크 전체 클래스에 필터를 붙이지 않는다.
4. 아래 비교 시험 명령을 실행해 프로그램이 새 VHDX를 생성·포맷하고 등록 대기할 때까지 기다린다.
5. UI `새로 고침` → 시험 디스크 후보 선택 → `필터 등록`을 누른다.
   해당 PnP 인스턴스의 `UpperFilters`에 이 필터만 추가하고 다른 항목·순서는 보존한다.
6. 시험 프로그램 안내에 따라 VHDX를 분리·재부착한다. UI를 새로고침하여 **커널 장치 목록**에
   표시되는지 확인한다. `필터 등록됨`은 레지스트리 등록일 뿐 실제 부착·방어를 뜻하지 않는다.
7. 해당 장치를 선택하고 `부트 영역 방어 시작`을 누른다. 영역 검사 완료 후 `방어 중`을 확인한다.
8. `부트 영역 방어 정지`는 선택한 장치만 정지한다. 다른 디스크의 상태를 바꾸지 않는다.
9. 시험 종료 후 정지 → `필터 등록 해제` → VHDX 분리 순으로 정리한다.
   등록 해제는 현재 붙어 있는 드라이버를 즉시 제거하지 않으며 패키지도 보존한다.

드라이버는 PnP로 부착되므로 `fltmc load`나 기존 프로세스 필터의 연결 버튼으로 활성화하지 않는다.
패키지 교체 전에는 UI를 닫고 시험 디스크를 분리하여 이전 드라이버의 사용을 끝내야 한다.
분리·제거에 실패하면 VM을 재부팅하고 상태를 확인한다. 광범위한 레지스트리 삭제로 우회하지 않는다.

신규 시험 인증서를 수동 설치할 경우 **인증서 출처를 확인한 시험 VM 내부**에서만 실행한다.

```powershell
Import-Certificate -FilePath .\UF_BootProtectionFactory.cer -CertStoreLocation Cert:\LocalMachine\Root
Import-Certificate -FilePath .\UF_BootProtectionFactory.cer -CertStoreLocation Cert:\LocalMachine\TrustedPublisher
```

## 4. 실제 차단 비교 시험

VM의 공용 `bin` 복사 폴더를 현재 위치로 한 관리자 PowerShell에서 실행한다.

```powershell
.\UF_BootProtectionTest.exe --vhdx-protection-test NTFS --confirm-disposable-vhdx
.\UF_BootProtectionTest.exe --vhdx-protection-test FAT32 --confirm-disposable-vhdx
```

각 시험은 자신의 새 256MiB VHDX만 사용하며 임의 디스크 경로를 받지 않는다. UI 방어 켬 상태의
기본·백업 부트 쓰기 거부와 바이트 보존, 동일 장치의 차단 횟수 증가를 확인한다. 이후 UI 방어 끔
상태에서 같은 쓰기가 성공하고 **해당 폐기용 VHDX만 실제 손상**되는지 비교한다.
두 단계 모두 확인할 때만 `result.json`의 `kernelProtectionVerified=true`가 된다.

기존 `--vhdx-damage`는 손상 재현만 하므로 해당 값이 false여도 정상이다.
`--all` 및 파서 자체 시험 통과는 실제 드라이버 차단의 증거가 아니다.

## 5. 상태·오류·로그 해석

| UI 항목 | 의미 |
| --- | --- |
| 상단 부트 필터 연결 | 제어 장치 QUERY 응답 성공 여부. 방어 중 여부와 별개 |
| 정지 | 필터 부착은 되어도 쓰기 차단을 하지 않음 |
| 영역 검사 중 | 시작 처리 중. 검증 중 변경 요청을 막고 선행 요청 종료를 기다림 |
| 방어 중 | 해당 부착 ID·정책 세대의 보호 구간 활성 |
| 시작 실패 / 미지원 | 배치·장치 조건 또는 상태 검증 실패. NTSTATUS 확인 필요 |
| 상태 확인 불가 | 통신 오류. 정지나 보호 성공으로 해석하지 말고 재조회 |
| 보호 범위 / 차단 횟수 | 커널이 반환한 실제 구간과 누적 거부 수 |
| 로그 지우기 | 화면만 초기화. 커널 보호·차단 횟수는 유지 |

로그에는 시각, 장치, 영역 종류, PID·생성 시각, 이미지 경로, 쓰기 위치·길이, IOCTL,
NTSTATUS, 정책 세대와 시퀀스를 표시한다. 경로 미확인은 숨기지 않는다. 커널 캐시에 없으면
UI가 같은 프로세스 핸들의 생성 시각을 대조해 읽기 전용으로 경로를 보완하고 출처를 표시한다.
이는 원시 요청자 정보이며 시스템 작업자·대리 I/O의 최초 행위자를 항상 입증하지는 않는다.

`logs\RansomUtilFactory.UI.log`에 버튼·응답·차단 이벤트,
`logs\uf_bootwarp.log`에 IOCTL 오류와 시작·정지 결과의 `GetLastError`를 기록한다.
차단 NTSTATUS와 사용자 모드 Win32 오류는 서로 다른 값이다. 큐 유실은 별도 누적 표시하며
로그를 놓쳤다고 차단을 허용하지 않는다. 이벤트 큐는 단일 UI 소비자를 전제로 한다.

## 6. 남은 검증과 제한

- 이 문서는 초기 개발 구현이다. VM 설치/부착과 실제 차단은 동적 시험을 별도로 통과해야 한다.
- 현재 자동 프로세스 종료·실행 파일 삭제·격리, 유지보수 허용, OS 부팅 디스크 보호는 없다.
- EFI 파일/BCD·UEFI 변수·악성 커널 드라이버·필터 로드 이전 또는 우회 경로는 보호 완료가 아니다.
- VM에서 FAT32/NTFS 비교, MBR/GPT 쓰기, 정상 파일 작업·FSInfo, UI 종료 후 차단 유지,
  반복 시작/정지, 이벤트 폭주, 동시 제거·전원, Driver Verifier를 시험해야 한다.
- 관리자가 필터·정책을 변경할 수 있으므로 관리자 권한 악성코드에 대한 변조 방지 경계가 아니다.
- 코드·ABI·빌드·호스트 안전 검사 결과는 아래 검증 기록에 실제 수행분만 기록한다.
