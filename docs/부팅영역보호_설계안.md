# 부팅 영역 보호 설계안

작성일: 2026-09-10

상태: 전체 목표 설계이며 모든 항목이 구현된 것은 아니다. 2026-09-14에 전용 데이터
VHDX용 KMDF 디스크 상위 필터, 별도 통신 DLL, UI 방어 시작·정지와 차단 로그를 추가했다.
현재 구현·설치 절차와 미검증 항목은 [부팅 영역 보호 사용법](부팅영역보호_사용법.md),
시험 모드는 [시험 프로그램 설명](부팅영역보호_시험프로그램.md)을 기준으로 한다.
OS 디스크 보호, 유지보수 예외, 자동 종료·격리는 아직 구현 완료 범위가 아니다.

## 1. 목적과 승인한 처리 원칙

FAT32·NTFS 부팅 영역에 대한 허가되지 않은 변경 시도를 디스크에 반영하기 전에
차단하고, 요청 프로세스와 대상 영역을 UI에 알린다. 사용자 모드는 확인 가능한
원인 프로세스를 종료하고 실행 파일을 복구 가능한 형태로 격리한다.

- 디스크 쓰기 차단은 신규 스토리지 필터가 담당한다.
- 쓰기 판정 중 UI 응답이나 사용자 모드 서명 확인을 기다리지 않는다.
- 자동 후속 조치는 종료·격리를 기본으로 한다. 영구 삭제는 별도 선택 동작으로 둔다.
- 경로만으로 종료·삭제하지 않는다. 프로세스와 실행 파일의 동일성을 각각 검증한다.
- SYSTEM 계정, PID 4, Windows 경로, 코드 서명만으로 쓰기를 일괄 허용하지 않는다.
- 기존 프로세스 실행 정책과 부팅 영역 보호 정책을 분리한다.

탐지 이름은 `부팅 영역 무허가 변경 시도`로 한다. 쓰는 데이터의 내용만 보고
랜섬웨어 여부를 확정하지 않는다. 정상 설치·업데이트·복구 도구도 같은 영역을
수정할 수 있으므로 제한된 유지보수 허용 정책이 필요하다.

## 2. 현재 코드와 신규 구성 요소

| 구성 요소 | 역할과 변경 범위 |
| --- | --- |
| `UF_BootProtectionFactory` 신규 | 스토리지 필터, 보호 영역 판정, 요청자 식별 자료 수집, 차단 이벤트 큐 |
| `uf_bootwarp` 신규 | 별도 제어 장치 연결, 정책·상태·이벤트 C ABI, 오류 변환 |
| UI 부팅 영역 보호 화면 신규 | 대상 디스크·보호 상태·정책 관리, 차단 및 후속 조치 표시 |
| 사용자 모드 조치 작업자 신규 | 동일성 검증, 종료, 격리 보관, 결과 기록. 초기 개발 도구에서는 UI의 별도 작업 큐 사용 |
| `UF_ProcessFilterFactory` 기존 | 실행 정책과 프로세스 생성·종료·접근 감시 유지. 디스크 I/O 차단을 이 콜백에 추가하지 않음 |
| `UF_FileFilterFactory` 기존 | 파일 경로 기반 감시·보호 유지. EFI 부팅 파일 보호 연동은 후속 단계 |

Microsoft는 스토리지 클래스 드라이버 위·아래의 필터 계층을 설명하고 있으며,
파일시스템 미니필터와 디스크 직접 접근의 감시 범위는 다르다.
따라서 현재 `PsSetCreateProcessNotifyRoutineEx` / `ObRegisterCallbacks`에 디스크
쓰기 조건만 추가하는 방식으로 요구사항을 충족했다고 판단하지 않는다.
[스토리지 필터](https://learn.microsoft.com/en-us/windows-hardware/drivers/storage/storage-filter-drivers),
[파일시스템 필터](https://learn.microsoft.com/en-us/windows-hardware/drivers/ifs/about-file-system-filter-drivers)

신규 필터는 KMDF 기반 디스크 상위 필터를 우선 검토한다. 최종 부착 위치는
시험 디스크에서 물리 디스크 핸들·볼륨 핸들 쓰기가 모두 관찰되는지 검증해 확정한다.
필터가 존재한다는 이유만으로 모든 저장장치 경로가 보호된다고 표시하지 않는다.

## 3. 보호 범위와 제외 범위

| 영역 | 계획 |
| --- | --- |
| FAT32 | 기본·백업 부트 영역을 유효한 파일시스템 정보와 장치 경계로 검증해 보호 |
| NTFS | 기본·백업 부트 영역을 유효한 파일시스템 정보와 장치 경계로 검증해 보호 |
| MBR | 디스크 시작 영역과 파티션 정보 보호를 별도 규칙으로 관리 |
| GPT | 기본·백업 헤더와 파티션 엔트리 영역을 별도 규칙으로 관리 |
| EFI 부팅 파일 / BCD | 부트 섹터와 구분. 후속 파일 필터 정책 연동으로 보호 |
| 펌웨어·UEFI 변수 | 이번 구현 범위 밖 |

UEFI Windows의 EFI 시스템 파티션은 FAT32를 사용하고 부팅에 쓰인다. 부트 섹터만
보호해도 EFI 파일까지 모두 보호한 것은 아니므로 두 기능의 상태를 분리한다.
[UEFI/GPT 파티션](https://learn.microsoft.com/en-ie/windows-hardware/manufacture/desktop/configure-uefigpt-based-hard-drive-partitions?view=windows-10)

영역 계산 규칙:

- 단위는 디스크 기준 64비트 바이트 오프셋과 길이다. 논리 섹터 크기도 함께 보관한다.
- 512바이트 섹터, 고정 파티션 시작 위치, 디스크 번호를 영구 식별자로 가정하지 않는다.
- 볼륨 상대 위치와 물리 디스크 상대 위치를 혼용하지 않는다. 검증된 매핑만 사용한다.
- 파일시스템의 전체 예약 영역을 무조건 부팅 영역으로 취급하지 않는다. FAT32 FSInfo
  등 정상 갱신 메타데이터는 별도 분류하고 무조건 차단하는 범위에 섞지 않는다.
- BPB, 파티션 정보, 백업 위치, 디스크 크기를 서로 대조한다. 모순되거나 지원하지
  않는 형식이면 `영역 확인 실패 / 미지원`으로 표시하고 차단 모드 활성화를 거부한다.
- 초기 지원은 시험 VHDX의 기본 디스크로 제한한다. 동적 디스크, Storage Spaces,
  RAID, 다중 디스크 볼륨과 특수 버스는 검증 전까지 지원한다고 표시하지 않는다.

관리자 권한이나 악성 커널 드라이버가 정책·필터 자체를 변조하는 공격, 드라이버
시작 전의 오프라인 변경, 필터를 우회하는 미지원 장치 경로까지 방어한다고 주장하지 않는다.

## 4. 정책과 활성 상태

### 4.1 정책의 논리 구조

| 항목 | 내용 |
| --- | --- |
| 정책 세대 | 드라이버가 성공한 정책 교체마다 증가시키는 값 |
| 장치 식별 | 장치 인스턴스 정보와 현재 부착 세대. 디스크 번호는 표시용 보조 값 |
| 보호 영역 | 영역 ID, 종류, 시작 바이트, 길이, 파티션 식별자, 검증 상태 |
| 동작 모드 | 비활성, 관찰, 차단 |
| 유지보수 허용 | 특정 프로세스 인스턴스·장치·영역·작업·만료 시각에 한정한 허용 |
| 후속 조치 | 차단만 또는 종료·격리. 영구 삭제는 기본 비활성 |

`연결됨`, `관찰 중`, `보호 활성`, `영역 확인 실패`, `미지원`, `장치 제거됨`을
각각 표시한다. 통신 연결만으로 `보호 활성`을 표시하지 않는다.

초기 설치는 자동으로 모든 디스크의 차단을 켜지 않는다. 관리자가 대상 장치를
선택하고 검증된 영역 목록을 확인한 후 활성화한다. 활성화 전과 재부팅 후 영역
검증 완료 전에는 보호 공백이 있음을 명시한다. 부팅 초기 보호는 별도 검증 단계다.

### 4.2 정상 시스템 작업의 허용

- `system.exe`, `System`, Windows 경로 또는 서명 여부만으로 신뢰하지 않는다.
- 승인된 유지보수 도구의 검증된 실행 파일 신원과 정확한 실행 인스턴스에 허용을 묶는다.
- 해당 장치의 지정 영역과 작업만 제한된 시간 동안 허용한다. 종료·만료·장치 세대
  변경·정책 교체 시 허용을 폐기한다. 자식 프로세스에 자동 상속하지 않는다.
- 서명 확인은 허용 등록 전에 사용자 모드에서 수행한다. 유효한 서명 자체는
  모든 부팅 영역 수정 권한을 의미하지 않는다.
- 커널·파일시스템 작업은 신뢰 가능한 경로와 필요한 수정 범위를 먼저 규정하고
  VM에서 정상 마운트·해제·종료·업데이트 동작을 시험한다. `KernelMode` 전체를
  통과시키거나 SYSTEM의 모든 쓰기를 거부하는 단순 분기를 사용하지 않는다.
- 원인 인스턴스를 안전하게 귀속할 수 없는 유지보수 요청은 온라인 허용 대상으로
  등록하지 않는다. 복구 환경 등 별도 승인 절차를 사용한다.

## 5. 쓰기 판정과 실패 처리

```text
검증한 장치의 변경 요청
  보호 영역과 겹치는지 / 영역을 바꾸는 명령인지 판정
    범위 밖의 지원 요청: 전달
    보호 대상이며 승인된 작업: 전달 후 결과 기록
    보호 대상이며 승인되지 않음: 하위 장치에 보내지 않고 차단
      차단 이벤트 큐 기록
      사용자 모드가 비동기로 수신하고 후속 조치
```

- `[시작, 끝)` 구간을 사용한다. 0 길이, 음수 위치, 합산 오버플로, 디스크 경계 초과,
  앞뒤 경계 교차, 큰 쓰기에 작은 보호 영역이 포함되는 경우를 검증한다.
- 보호 영역과 일부라도 겹치는 무허가 쓰기는 전체 요청을 거부한다. 부분 전달하지 않는다.
- 쓰기 데이터 내용을 읽거나 서명을 확인하지 않고 검증된 범위·허용 정보로 판정한다.
- 상태·정책 조회는 서명·종료·격리 작업과 같은 잠금이나 대기 큐를 공유하지 않는다.
- 활성 보호 영역의 무허가 쓰기는 경로 조회 실패, 사용자 모드 부재, 큐 포화에도
  차단한다. 후속 조치 실패를 쓰기 허용으로 바꾸지 않는다.
- 큐 포화 시 유실 수를 기록하고 I/O는 기다리지 않는다. 장치별 차단 횟수는 별도 유지한다.
- 클라이언트 연결 해제는 활성 정책을 해제하지 않는다. 드라이버 언로드·장치 제거·
  명시적 비활성 및 재부팅으로 생기는 보호 공백은 별도로 표시하고 감사 기록에 남긴다.
- 장치 번호 재사용만으로 정책을 새 디스크에 적용하지 않는다. 레이아웃 변경은 활성
  상태에서 별도 승인 대상으로 취급하고, 승인 변경 후에는 새 영역 검증을 끝내고 재개한다.

일반 `IRP_MJ_WRITE`만 막은 단계는 최종 완료로 간주하지 않는다. 파티션 배치 변경,
디스크 초기화·포맷, TRIM/UNMAP, SCSI/ATA/NVMe 전달 명령 등 저장 내용을 바꿀 수
있는 제어 경로를 목록화하고 지원 대상 스택에서 검증한다. 범위를 판정할 수 없는
변경 명령은 활성 보호 장치에서 거부하는 방향으로 검토하되, 정상 스토리지 동작과
PnP·전원·조회 명령을 손상시키지 않는 명령 분류 시험을 완료해야 한다.

파일시스템의 볼륨 경계 검사도 모든 원시 접근을 막는 보안 경계로 가정하지 않는다.
Microsoft는 확장 DASD I/O에 대한 주의와 파티션 손상 가능성을 설명한다.
[FSCTL_ALLOW_EXTENDED_DASD_IO](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_allow_extended_dasd_io)

## 6. 요청 프로세스 식별

기존 `ProcList`에는 실행 정책을 통과한 등록 프로세스만 들어간다. 신규 보호에서
이를 전체 프로세스 목록으로 사용하면 미등록 프로세스의 공격을 놓친다.

- 신규 보호 경로는 실행 정책 등록 여부와 무관하게 요청자 정보를 수집해야 한다.
- IRP 요청자와 해당 실행 인스턴스를 조기에 확보하고 객체 참조의 수명을 관리한다.
- 디스크 I/O를 처리하는 현재 스레드의 PID를 곧바로 원인 PID로 기록하지 않는다.
- `IoGetRequestorProcess`는 IRP 관련 프로세스를 얻는 API이며, 반환값과 요청의 생성·
  전달 경로를 검증해야 한다. 반환된 값 하나로 최초 행위자를 항상 특정했다고 보지 않는다.
  [요청 프로세스 API](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-iogetrequestorprocess)
- 프로세스 식별은 부팅 세션 식별자, PID, 생성 시각 또는 재사용하지 않는 인스턴스
  토큰을 함께 사용한다. 경로 문자열은 표시 자료이며 종료 대상의 식별 키가 아니다.
- 이미지 경로와 파일 신원은 생성/열기 시점에 안전하게 확보하는 방식을 우선한다.
  I/O 차단 경로에서 디스크 파일을 다시 열어 교착을 유발하지 않는다.
- 시스템 작업자, 대리 요청, 경로 미확인, 오래된 캐시 등은 `요청자 미확인` 또는
  `귀속 불충분`으로 기록한다. 차단을 유지하되 자동 종료·격리는 하지 않는다.
- 시스템 핵심 프로세스·보호 프로세스는 자동 종료 대상에서 제외한다. 그렇다고
  해당 프로세스의 모든 보호 영역 쓰기를 허용하는 예외로 사용하지 않는다.

## 7. 사용자 모드 종료·격리

### 7.1 종료

1. 차단 이벤트의 세션·장치·정책·시퀀스와 귀속 상태를 검증한다.
2. PID로 핸들을 열고 생성 식별자를 비교한다. 불일치하면 다른 프로세스이므로 중지한다.
3. 핵심·보호 프로세스, 미확인 요청자, 종료된 프로세스와 자동 조치 제외 대상을 구분한다.
4. 검증한 동일 핸들로 종료를 요청하고 제한 시간 안에 종료 완료를 확인한다.
5. 종료 실패·시간 초과·이미 종료 상태를 별도 기록한다. 실패해도 쓰기 차단은 유지한다.

### 7.2 격리

1. 경로만 다시 열어 현재 그 위치의 파일을 옮기지 않는다. 이벤트에 묶인 이미지 파일
   신원과 열린 파일 핸들의 볼륨 식별자·파일 ID를 검증한다. 필요 시 해시를 보강한다.
2. 재분석 지점, 링크, 경로 교체와 동시 변경을 검사한다. 안전한 동일성 검증이 없으면
   `격리 보류`로 남기고 파일을 이동하거나 삭제하지 않는다.
3. 가능하면 종료 전에 검증한 파일 핸들을 확보하고 이후 같은 객체를 대상으로 조치한다.
   공유 모드나 이미지 매핑으로 확보할 수 없으면 우회·강제 삭제하지 않고 실패를 기록한다.
4. 관리 권한으로만 접근할 수 있는 격리 저장소에 실행할 수 없는 보관 형식으로 저장한다.
   단순 확장자 변경만으로 격리 성공이라 하지 않는다. 원본 경로·파일 ID·해시·시각·
   이벤트 ID를 보관하고, 저장과 확인을 완료하기 전에 원본을 삭제하지 않는다.
5. 다른 볼륨으로 복사하는 경우 원자적 이동이라고 주장하지 않는다. 원본 제거 실패,
   잔여 하드링크, 다른 복제본이 있으면 `격리 부분 완료`로 표시한다.
6. 일반 파일 내용이 기록된 격리 자료는 민감 자료로 취급한다. UI 진단 로그에는
   실행 파일 본문이나 자격 증명을 기록하지 않는다.

파일 신원 조회에는 핸들 기반 파일 정보 API를 사용한다. 파일 ID 확인만으로 내용의
동시 변경까지 방지한 것은 아니므로 핸들 수명·공유·변경 검증을 함께 설계한다.
[GetFileInformationByHandleEx](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getfileinformationbyhandleex)

### 7.3 영구 삭제와 복원

- 기본 자동 동작에는 영구 삭제를 포함하지 않는다.
- 관리자가 격리 항목의 신원과 결과를 확인한 후 별도로 영구 삭제한다.
- 삭제 시 기존 경로의 파일을 다시 찾아 삭제하지 않고 검증된 격리 항목을 대상으로 한다.
- 복원도 관리자 확인 후 수행하며 기존 파일을 자동 덮어쓰지 않고 자동 실행하지 않는다.
- 사용자 모드 조치 작업은 시간 제한과 동시 실행 상한을 둔다. 같은 사건의 재수신은
  중복 종료·격리를 일으키지 않도록 사건 ID별 상태를 저장한다.

초기 UI 기반 작업자는 UI가 꺼져 있으면 후속 조치를 수행할 수 없다. 이 경우에도
커널의 활성 차단은 유지한다. 상시 조치가 필요하면 후속 제품화 단계에서 권한 있는
전용 서비스로 분리한다. 현재 UI만으로 재부팅을 넘는 상시 복구를 보장하지 않는다.

## 8. 신규 통신 규약의 논리 필드

기존 파일·프로세스 V2 ABI를 재해석하지 않는다. 별도 제어 장치와 `UF_BOOT_` 이름
공간을 사용한다. 아래는 후속 기능까지 포함한 목표 논리 설계다. 2026-09-14 초기 V1의
실제 IOCTL·크기·상한은 `include/uf_boot_protocol.h`와 [통신규약](통신규약.md)의
11절에 확정했다. 초기 V1에는 유지보수 예외·파일 신원·격리 결과·재수신 커서가 없다.

| 메시지 | 주요 내용 |
| --- | --- |
| 공통 헤더 | Version, Size, RequestId, 예약 필드. 포인터·커널 HANDLE 금지 |
| 상태 조회 | DriverSessionId, 장치별 부착·지원·활성 상태, 정책 세대, 큐 깊이·유실 수, 실제 지원 경로 |
| 영역 조회 | 장치 식별자, 레이아웃 세대, 검증한 보호 영역 ID·종류·오프셋·길이·섹터 크기 |
| 정책 교체 | ExpectedGeneration, 장치·영역 ID 목록, 모드, 사전에 검증된 제한 허용 |
| 이벤트 조회 | 세션과 시퀀스 커서, 제한된 배치, 유실 정보. UI 미연결 중에도 제한 큐 유지 |
| 차단 이벤트 | 정책·장치·영역 ID, 쓰기 위치·길이·요청 종류, NTSTATUS, 요청자 귀속 수준 |
| 프로세스 정보 | PID, 생성 식별자, 이미지 경로와 조회 상태, 검증 가능한 이미지 파일 신원 |
| 후속 조치 기록 | 사건 ID, 종료 상태, 격리 상태, Win32 오류, 검사 단계, 보류 이유 |

통신 장치는 SYSTEM·Administrators만 접근하도록 제한한다. 읽기와 변경 명령의
권한을 구분한다. 관리자 ACL은 이미 관리자 권한을 탈취한 공격자에 대한 변조 방지를
보장하지 않으며, 전용 서비스 신원과 정책 보호 강화는 별도 보안 경계로 설계한다.

정책 전체를 검증한 후 원자적으로 교체한다. 세대 불일치·크기·개수·문자열·범위·
예약 필드 오류는 기존 정책을 유지하며 거부한다. 이벤트 큐는 유한 크기이며 커서
재수신·중복·오버런을 식별한다. 소비자는 세션 변경을 인지하고 이전 허용·사건을
새 드라이버 세션에 재사용하지 않는다.

## 9. UI 구성

프로세스 제어 기능과 연관시키되 별도 `부팅 영역 보호` 화면을 추가한다.

- 상단에 세 번째 드라이버의 연결 상태를 표시하고, 화면 내부에 실제 보호 활성
  장치와 영역 수, 미지원·검증 실패 상태를 따로 표시한다.
- 버튼: 연결·해제, 대상 새로고침, 영역 조회, 관찰/차단 정책 적용, 보호 비활성,
  유지보수 허용 등록·해제, 로그 지우기, 격리 목록, 복원, 영구 삭제.
- 설치·부착은 시험 장치 지정과 복구 절차 확인을 별도로 요구한다. 기존 프로세스
  드라이버의 설치 버튼으로 전체 디스크 클래스에 필터를 자동 등록하지 않는다.
- 로그 열: 시각, 디스크·볼륨, 보호 영역, 요청 종류, 위치·길이, 차단 결과,
  PID·생성 식별자, 프로세스 경로, 귀속 수준, 종료 결과, 격리 결과, 오류 코드.
- 최초 표시 메시지는 `부팅 영역 쓰기 차단`이다. 종료·격리 완료를 미리 표시하지 않는다.
- `GetLastError` / Win32 코드와 커널 NTSTATUS를 구분하고 실제 실패 단계에서 수집한다.
- 기존 `AppliedProcessLogPolicy`로 부팅 차단 이벤트를 필터링하지 않는다. 프로세스
  이름 정책 미등록과 관계없이 활성 부팅 보호의 사건은 표시한다.
- `로그 지우기`는 화면만 비운다. 보호 정책·감사 기록·격리 자료를 삭제하지 않는다.

## 10. 구현 순서와 완료 기준

| 단계 | 산출물 | 다음 단계 진입 조건 |
| --- | --- | --- |
| 1 | 보호 구간·명령 판정 모듈, 합성 단위 시험 | 경계·오버플로·장치 세대·허용 만료 시험 통과 |
| 2 | 신규 드라이버·DLL·상태/이벤트 통신, 관찰 모드 | 전용 데이터 VHDX에 한정한 부착·제거·PnP·전원·취소 시험 통과 |
| 3 | 검증한 영역 쓰기 차단 | 물리 디스크·볼륨 경로 차단 및 전후 영역 해시 일치 확인 |
| 4 | 요청자 동일성 검증·종료·격리 작업자 | PID 재사용·경로 교체·격리 실패·중복 사건 시험 통과 |
| 5 | UI 연동과 유지보수 정책 | 기존 두 탭 회귀 및 미등록 프로세스 차단 알림 확인 |
| 6 | 우회 제어 경로와 부팅 볼륨 지원 | 지원 대상별 명령 분류, 업데이트·복구·재부팅·Verifier 시험 통과 |

새 프로젝트는 Debug/Release x64 공용 `bin` 복사 단계를 포함한다. 소스·프로젝트
변경 후 전체 Debug x64 Rebuild, 드라이버·배포 변경 후 Release x64도 검증한다.
컴파일 성공, VM 로드 성공, 차단 검증, 후속 조치 검증을 각각 따로 기록한다.

## 11. 시험 시나리오

시험은 체크포인트와 복구 매체를 확보한 Win11 VM에서 별도 데이터 VHDX부터 시작한다.
개발 호스트의 물리 디스크와 VM의 실제 OS 부팅 디스크를 초기 시험 대상으로 사용하지 않는다.
합성 시험은 실제 디스크 쓰기 없이 구간 판정과 사건 처리 상태 전이를 검증한다.

| 분류 | 필수 시험 |
| --- | --- |
| 구간 | 영역 앞·뒤·내부, 경계 걸침, 전체 포함, 0 길이, 오버플로, 디스크 끝 |
| 배치 | FAT32·NTFS 기본/백업, MBR·GPT, 512e·4Kn, 손상·모순 메타데이터 |
| 전달 경로 | 물리 디스크/볼륨 핸들, 일반 쓰기, 지원 대상 변경 IOCTL, 필터 미부착 대상 |
| 허용 | 올바른 유지보수 허용, 다른 PID/생성 시각/디스크/영역, 만료·정책 교체 |
| 시스템 안정성 | 마운트·해제·종료·업데이트·복구·장치 제거·전원 전환 |
| 정보 부족 | 경로 없음, 귀속 불충분, 시스템 작업자. 쓰기 차단과 자동 조치 보류 확인 |
| 수명 | PID 재사용, 원인 프로세스 선종료, 장치 번호 재사용, 드라이버 재시작 |
| 격리 | 파일 교체·재분석 지점·하드링크·공유 위반·보관 공간 부족·부분 실패 |
| 통신 | UI 부재·종료·재연결, 큐 포화·중복·유실, 정책 적용 중 조회·취소 |
| 회귀 | 파일 정책과 프로세스 실행 정책의 기존 동작, UI 응답성, 오류 로그 |

차단 시험은 요청 실패 코드만 확인하지 않는다. 시험 영역의 전후 해시와 실제 내용이
변하지 않았는지 별도 읽기로 확인한다. 허용 시험과 격리·복원 시험은 폐기 가능한
시험 데이터만 사용하며 정상 앱이나 OS 파일을 자동 종료·격리하는 시험을 하지 않는다.
