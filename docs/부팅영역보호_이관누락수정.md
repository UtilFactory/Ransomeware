# 부팅 영역 보호 이관 누락 수정

작성일: 2026-09-15 · 브랜치: `tsk/8/main`

## 1. 보고와 확인 범위

사용자는 부트 보호가 정상적으로 시작된 뒤 악성코드 시험을 했으나 방어되지 않았고,
VM이 부팅되지 않아 새 로그를 확보할 수 없다고 보고했다. 앞선 로그에서 확인했던
구형 DriverStore 패키지 및 프로세스 DLL 로드 오류를 이번 미차단의 확정 원인으로
사용하지 않는다. 손상 위치·요청 모드·실제 I/O 경로는 확보되지 않았다.

참고 구현과 현재 소스를 대조하여 동작 차이는 확인했다. 이 수정은 그 차이와 검사
실패 통과를 보완한 것이며, 해당 악성코드의 원인 규명이나 VM 실방어 성공을 의미하지 않는다.
참고 구현을 제공받아 통합·보완한 경위와 이번 수정은 구분한다.

## 2. 수정 내용

1. `driver.c`에서 원시 쓰기 부트 분기를 일반 파일 정책의 KernelMode 제외보다 먼저
   처리한다. 일반 파일 정책은 이전처럼 커널 기원 I/O를 제외한다.
2. `boot_guard.c`의 KernelMode 전체 및 PID 0/4 일괄 예외를 제거한다. 비페이징 커널
   쓰기도 검사한다. 원본의 KernelMode이면서 페이징 I/O인 예외와 참조된 현재 관리
   클라이언트 예외는 유지한다. KernelMode와 정상 시스템 유지보수 허용은 같은 의미가 아니다.
3. 활성 상태에서 원시 볼륨/장치로 분류된 선두 2KiB 쓰기는 대상 재검증·MDL 잠금·
   메모리 할당·작업 큐·재열기·읽기·비교 실패 때 통과시키지 않고 `STATUS_ACCESS_DENIED`,
   완료 바이트 0으로 끝낸다. 이미 정지했거나 관리 클라이언트로 바뀐 요청에는 새 차단을
   적용하지 않는다. 오류 알림 전송 실패는 차단 결정을 취소하지 않는다.
4. 1MiB 전체 쓰기 스냅숏과 동시 16개 제한은 메모리 안전을 위해 유지하되 초과 요청은
   검사 실패 차단으로 처리한다. 한도를 없애거나 읽기 실패를 안전하다고 간주하지 않는다.
5. 동일 선두 바이트를 허용할 때는 승인한 스냅숏만 하위 계층으로 전달한다. 버퍼 변경
   경쟁을 다시 만들거나 잠금 없는 사용자 포인터를 worker에서 읽는 원복은 하지 않는다.
6. `[UF][boot] revision=20260915.1`에 단계·원래 NTSTATUS·PID/TID·모드·IRQL·IRP flags·
   위치·길이를 기록한다. 실패 원인은 커널 진단에 남기고 UI에는 차단 결과를 구분한다.

## 3. 통신과 화면

- SET 5/QUERY 6, 파일 규약 V2, SET 24바이트·상태 40바이트·기존 이벤트 크기를 유지한다.
- Action 5: 실제 내용 변경 차단. Action 6: 기존 버전의 검사 실패 후 통과.
  새 Action 7: 검사 실패 후 차단. 화면에는 `부트 쓰기 차단 — 검사 오류`로 표시하여
  차단 결과를 먼저 알린다. 기존 6을 차단 의미로 재해석하지 않는다.
- 검사 실패 차단은 차단 수와 실패 수 양쪽에 포함된다. UI 실패 합계의 `(통과)` 표기를
  없애고 툴팁으로 중복 집계 의미를 알린다. CLI·V2/기존 콜백도 5/6/7을 구분한다.
- UI의 `설정 활성`은 드라이버 활성 플래그 확인이다. 콜백 도달·전체 디스크 경로·
  실제 바이트 보존을 시험했다는 표시가 아니다.
- 최신 커널 식별 표식은 `file-boot-failclosed-20260915.1/Debug` 또는 `/Release`이다.
  빌드 파일 복사만으로 설치된 드라이버가 바뀌지 않으므로 패키지 갱신/재로드를 확인한다.

## 5. 배포와 남은 제한

- 생성물 위치는 `x64/Debug/bin`, `x64/Release/bin`이다. 같은 구성의 SYS/INF/CAT,
  DLL·UI를 함께 배포해야 한다. 이번 작업에서는 호스트/VM 드라이버 설치·로드를 하지 않았다.
- 사용자의 부팅 불가 VM·검사점·가상 디스크와 로그 파일을 변경하지 않았다. 복구는 별도
  작업이며 악성코드 재실행은 하지 않았다. 깨끗한 격리 VM 검사점에서 비악성 검증을 먼저
  수행해야 한다. 기존 손상 도구 실행 성공을 방어 시험 성공으로 사용하지 않는다.
- 콜백에 도달하지 않는 직접 디스크 I/O, 원시 대상 분류 자체에 실패하는 요청, 선두
  2KiB 밖의 전체 GPT 엔트리·백업 GPT·EFI 영역은 이번 수정으로 보호 완료가 되지 않는다.
  관리 클라이언트·커널 페이징 예외도 남는다. [2차 계획](부팅영역보호_2차계획.md)은 미착수다.
- 확인한 보호 구간의 정상 쓰기도 비교 불가/상한 초과면 거부할 수 있다. 일반 OS 작업,
  디스크 관리·업데이트·복구·잠긴 볼륨·시작/정지·언로드 호환성을 VM에서 검증해야 한다.
- 실제 차단 확인은 설정 성공뿐 아니라 콜백 도달, API 거부 결과, 차단/실패 수,
  시험 전후 보호 구간 내용 보존을 함께 확인해야 한다. 실방어 완료로 배포하지 않는다.

## 6. API 확인 자료

- [FltLockUserBuffer](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/fltkernel/nf-fltkernel-fltlockuserbuffer): 사용자/시스템 버퍼 잠금, MDL 생성과 소유권.
- [FltQueueDeferredIoWorkItem](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/fltkernel/nf-fltkernel-fltqueuedeferredioworkitem): 작업 큐와 페이징/재귀 I/O 제한.
- [FltCreateFileEx2](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/fltkernel/nf-fltkernel-fltcreatefileex2): 인스턴스 아래쪽 재열기, 공유 및 호출 문맥 제약.
