# RansomUtilFactory 파일 필터 통신 규약

## 1. 적용 범위

이 문서는 `UF_FileFilterFactory.sys`와 `uf_fltwarp.dll` 사이의 통신 규약을 정의한다.
공유 형식의 기준 헤더는
`UF_FileFilterFactory/include/uf_filefilter_protocol.h`이다.

현재 통신 규약 버전은 `UF_PROTOCOL_VERSION` 값 `2`이다. 기존 V1 보호 목록은
서명 검증 정보를 포함하지 않으므로 V2 드라이버에서 보호 정책으로 사용하지 않는다.

## 2. 연결 방식

- 드라이버는 `\UF_FileFilterFactoryPort` 이름으로 필터 관리자 통신 포트를 생성한다.
- DLL은 `FilterConnectCommunicationPort`로 연결한다.
- 동시에 연결할 수 있는 사용자 모드 클라이언트는 한 개이다.
- DLL에서 드라이버로 보내는 명령은 `FilterSendMessage`를 사용한다.
- 드라이버 이벤트는 `FltSendMessage`로 보내고 DLL은 `FilterGetMessage`로 수신한다.
- 포트 보안 설명자는 권한이 있는 관리 구성 요소만 연결할 수 있도록 제한한다.

별도의 `DEVICE IOCTL`은 파일 미니필터 통신에 사용하지 않는다. 추후 제어 장치가
필요해지면 통신 포트와 역할이 중복되지 않도록 별도 규약 버전에서 정의한다.

## 3. 공통 ABI 규칙

- 공개 구조체는 C ABI와 Windows 고정 폭 기본 형식을 사용한다.
- 모든 명령은 `UF_MESSAGE_HEADER`로 시작한다.
- `Version`은 송신 측 통신 규약 버전이고 `Size`는 전체 구조체의 바이트 크기이다.
- 예약 필드는 송신 전에 0으로 초기화한다. 단, `UF_PROTECTED_PROCESS_RULE.Reserved16`과
  `UF_FLT_PROTECTED_PROCESS_INPUT.Reserved`는 서명 확인·프로세스 이름 비교 플래그로 사용한다.
- 문자열은 UTF-16이며 길이 필드는 종결 문자 `L'\0'`을 제외한 문자 수이다.
- 배열의 사용 개수는 대응하는 개수 필드로 결정하며 `UF_MAX_RULES`를 넘을 수 없다.
- 구조체를 변경할 때 기존 필드의 순서나 의미를 바꾸지 않고 통신 규약 버전을 올린다.

## 4. 정책 명령

### `UfCommandReplacePolicy`

`UF_REPLACE_POLICY` 전체를 한 번에 전달하여 현재 정책을 원자적으로 교체한다.

- `PathRules`는 `UfRuleMonitor` 또는 `UfRuleAllowList` 폴더 규칙을 담는다.
- `MonitorExceptions`는 감시 알림에서 제외할 전체 프로세스 이미지 경로를 담는다.
- `AllowedImages`는 접근 제한 폴더에 접근할 수 있는 전체 프로세스 이미지 경로를 담는다.
- 일부 항목만 적용하는 동작은 허용하지 않는다. 하나라도 잘못되면 전체 요청을 거부한다.

### `UfCommandClearPolicy`

현재 경로, 감시 예외 및 허용 프로그램 목록을 모두 초기화한다.

### `UfCommandQueryState`

`UF_STATE_REPLY`로 현재 규칙 개수와 사용자 모드 연결 상태를 반환한다. 이 응답은
정책 내용 전체를 반환하지 않으며 진단과 UI 상태 표시에 사용한다.

### V2 보호 폴더 정책

`UF_REPLACE_POLICY_V2`는 경로·프로세스·서명자·폐기 정책을 한 번에 교체한다.

- `UF_PATH_RULE_V2.RuleId`는 보호 폴더 규칙을 식별한다.
- 보호 폴더마다 `UF_PROTECTED_PROCESS_RULE`을 하나 이상 지정할 수 있다.
- `Access`는 `PF_ACCESS_READ`와 `PF_ACCESS_WRITE`를 독립적으로 조합한다.
- 프로세스 비교 방식은 규칙별로 전체 경로와 실행 파일 이름 중 하나를 선택한다.
- 전체 경로 비교는 DLL이 DOS 경로를 NT 경로로 변환한 뒤 커널에서 수행한다.
- 실행 파일 이름 비교는 양쪽 경로의 마지막 구성 요소만 사용한다. 비교 문자는 커널에서
  소문자 기준으로 정규화하며, 표시용 회사명은 ABI 식별자로 사용하지 않는다.
- `UF_PROCESS_RULE_FLAG_REQUIRE_CODE_SIGNATURE`를 지정한 허용 프로세스는 사용자 모드에서
  로컬 코드 서명을 확인하고, 인증서 지문을 포함한 `UF_SIGNER_RULE`을 함께 전송한다.
- 해당 플래그를 지정하지 않고 `SignerRuleId`를 0으로 둔 허용 프로세스는 코드 서명을
  확인하지 않으며, 폴더·선택한 프로세스 비교 방식·접근 권한만 일치할 때 허용한다.
- 코드 서명 확인을 끈 규칙은 실행 파일 교체를 탐지하는 인증서 식별을 사용하지 않으므로
  UI에서 보안상 주의 문구를 표시해야 한다.
- `UF_SIGNER_RULE`은 인증서 SHA-256 지문 또는 발급자 SHA-256 지문과 일련번호를 사용한다.
- 사용자 모드 DLL은 `WinVerifyTrust`로 로컬 서명 신뢰를 확인한 뒤 `UfFltSetProcessTrust`를 호출한다.
- 드라이버는 PID와 프로세스 생성 시각을 함께 확인하고 서명자 지문·발급자·일련번호를 다시 대조한다.
- 정책 세대가 바뀌면 기존 신뢰 캐시를 모두 폐기한다.

### 폐기 확인

- 온라인 폐기 확인 여부와 시간 초과 동작은 `UF_REVOCATION_POLICY`로 전달한다.
- 네트워크 확인은 사용자 모드의 작업 스레드에서 수행하며 드라이버는 네트워크를 기다리지 않는다.
- `UfFltGetImageSignerIdentityWithTimeout`은 지정 시간 안에 끝나지 않으면 `ERROR_TIMEOUT`을 반환한다. 호출자는 `Trusted`와 정책의 시간 초과 동작을 함께 사용해 임시 허용 또는 차단을 결정한다.
- 허용 결정은 프로세스 생성 식별자와 정책 세대에 묶인다.
- 폐기 확인 결과가 나오면 `UfTrustInvalidate`로 캐시를 즉시 무효화하고, 종료가 필요한 경우
  사용자 모드에서 같은 PID와 생성 시각을 다시 확인한 뒤 종료한다.

## 5. 파일 이벤트

드라이버는 `UF_FILE_EVENT_V2`를 전송한다. 기존 공개 콜백을 사용하는 DLL 호출자는
기본 필드만 `UF_FILE_EVENT`로 변환된 이벤트를 받을 수 있다.

- `ProcessId`: 접근을 요청한 프로세스 식별자
- `DesiredAccess`: 생성 요청의 접근 권한
- `Disposition`: 생성 또는 열기 처리 방식
- `Action`: `UfEventObserved` 또는 `UfEventDenied`
- `Path`: 정규화된 NT 파일 경로
- `Image`: 요청 프로세스의 전체 이미지 경로
- `Operation`, `RequestedAccess`: 접근 종류와 읽기·쓰기 권한 비트
- `FolderRuleId`, `ProcessRuleId`: 적용된 정책 규칙 식별자
- `TrustDecision`, `ProcessCreateTime`, `PolicyGeneration`: 신뢰 결정과 PID 재사용 방지 정보

이벤트는 감사와 탐지 입력이다. 알림 수신 성공 여부를 파일 접근 허용의 필수 조건으로
사용하지 않는다. 차단 결과는 드라이버가 이미 적용한 정책을 나타낸다.

## 6. 경로 및 문자열 규칙

- 폴더 정책 경로는 `\Device\HarddiskVolume3\Protected`와 같은 정규화된 NT 경로이다.
- 사용자에게 입력받은 `C:\Protected` 형식은 DLL에서 NT 장치 경로로 변환한다.
- 비교는 대소문자를 구분하지 않는다.
- 폴더 규칙은 경로 구성 요소 경계를 기준으로 적용한다. 예를 들어 `Protected` 규칙이
  `ProtectedBackup` 폴더와 일치해서는 안 된다.
- 루트 이외의 폴더 경로는 마지막 구분자를 제거한 형태로 전송한다.
- 프로세스 규칙은 정규화된 전체 이미지 경로 또는 경로의 마지막 파일 이름을 사용한다.
- 프로세스 이미지 비교는 대소문자를 구분하지 않으며 커널에서 소문자 기준으로 비교한다.
- 입력 문자열은 최대 길이보다 짧아야 하며 구조체의 남는 영역은 0으로 초기화한다.

## 7. 오류 및 연결 해제

- 버전이 다르면 `STATUS_REVISION_MISMATCH`를 반환한다.
- 구조체 크기가 명령에 맞지 않으면 `STATUS_INFO_LENGTH_MISMATCH`를 반환한다.
- 개수, 모드 또는 문자열 길이가 범위를 벗어나면 `STATUS_INVALID_PARAMETER`를 반환한다.
- 지원하지 않는 명령은 `STATUS_INVALID_DEVICE_REQUEST`를 반환한다.
- 출력 버퍼가 작으면 `STATUS_BUFFER_TOO_SMALL`을 반환한다.
- 이미 클라이언트가 연결되어 있으면 추가 연결을 `STATUS_DEVICE_BUSY`로 거부한다.
- DLL의 드라이버 요청은 최대 5초 동안 응답을 기다리며, 시간이 지나면
  `ERROR_TIMEOUT`을 반환한다. 시간 초과가 발생한 요청은 사용자 모드에서 실패로
  표시하고 같은 정책을 자동으로 재전송하지 않는다.

클라이언트 연결이 끊어지면 감시 이벤트는 전송하지 않고 파일 입출력을 통과시킨다.
이미 적용된 `UfRuleAllowList` 차단 정책은 명시적으로 정책을 초기화하거나 드라이버를
언로드할 때까지 유지한다. DLL과 UI는 재연결 후 상태를 조회하고 저장된 전체 정책을
다시 전송하여 사용자 모드 상태와 드라이버 상태를 일치시킨다.

## 8. 버전 호환성

- 버전 2는 동일한 구조체 크기와 필드 배치를 사용하는 DLL과 드라이버 조합만 지원한다.
- 서명 확인 플래그는 기존 예약 필드의 의미를 확장하므로 구조체 크기는 변하지 않는다.
  `SignerRuleId`가 0인 규칙은 서명 확인을 하지 않는 새 동작이며, 기존 클라이언트가
  `SignerRuleId`를 지정한 규칙은 이전처럼 서명 확인 규칙으로 처리한다.
- V1 구조체를 사용한 보호 목록 요청은 서명 검증을 우회하지 않도록 거부한다.
- DLL은 연결 직후 상태 조회로 버전을 확인한 뒤 다른 명령을 보내야 한다.
- 알 수 없는 상위 버전을 자동으로 하위 버전으로 해석하지 않는다.
- 호환되지 않는 조합은 정책을 적용하지 않고 UI에 명확한 버전 오류를 표시한다.
- 규약 변경 시 이 문서, 공유 헤더, DLL 공개 헤더 및 P/Invoke 선언을 같은 변경에서 갱신한다.

## 9. `uf_fltwarp` 공개 C ABI

공개 선언의 기준 헤더는 `uf_fltwarp/include/uf_fltwarp.h`이다. 모든 함수는
`extern "C"` 호환 선언과 `__stdcall` 호출 규약을 사용하며 성공 시
`ERROR_SUCCESS`를 반환한다.

- `UfFltInitialize`, `UfFltShutdown`: 라이브러리 수명 주기 관리
- `UfFltConnect`, `UfFltDisconnect`, `UfFltIsConnected`: 통신 포트 연결 관리
- `UfFltReplacePolicy`: DOS 경로 입력을 변환한 후 전체 정책 원자적 교체
- `UfFltClearPolicy`, `UfFltQueryState`: 정책 초기화와 상태 조회
- `UfFltStartEventReceiver`, `UfFltStopEventReceiver`: 비동기 이벤트 콜백 관리
- `UfFltDosPathToNtPath`: 로컬 DOS 경로를 NT 장치 경로로 변환
- `UfFltGetErrorMessage`: Win32 오류 코드의 시스템 메시지 조회
- `UfFltReplacePolicyV2`: 보호 폴더, 허용 프로세스, 서명자 및 폐기 정책의 원자적 교체
- `UfFltQueryStateV2`: V2 정책 세대와 신뢰 캐시 상태 조회
- `UfFltGetImageSignerIdentity`: 사용자 모드 로컬 서명 신뢰와 인증서 식별 정보 조회
- `UfFltGetImageSignerIdentityWithTimeout`: 온라인 폐기 확인을 제한 시간으로 수행하는 비동기 작업 기반 조회
- `UfFltSetProcessTrust`: PID·생성 시각·서명자 식별 정보에 대한 신뢰 결정 전달
- `UfFltStartEventReceiverV2`: V2 파일 이벤트 콜백 등록
- WPF UI는 `UfEventTrustRequired` 이벤트를 받으면 사용자 모드에서 서명을 다시 확인하고 `UfFltSetProcessTrust`로 허용 또는 거부를 전달한다.

`UF_FLT_POLICY_INPUT`이 받는 문자열과 배열은 호출이 반환될 때까지만 유효하면 된다.
DLL은 입력을 고정 크기 통신 구조체로 복사한 후 드라이버에 보낸다. 이벤트 콜백으로
전달되는 `UF_FILE_EVENT` 포인터는 콜백 실행 중에만 유효하므로 보관하려면 호출자가
내용을 복사해야 한다.

## 10. 프로세스 필터 통신 규약 V2

### 10.1 적용 범위와 연결 방식

`UF_ProcessFilterFactory.sys`와 `uf_procwarp.dll`은
`UF_ProcessFilterFactory/include/uf_processfilter_protocol.h`를 공유한다. 프로세스
규약 버전은 `UF_PROC_PROTOCOL_VERSION` 값 `2`이다.

- 드라이버는 `\\.\UF_ProcessFilterFactory` 제어 장치를 제공한다.
- 장치 ACL은 `SYSTEM`과 로컬 `Administrators`에만 전체 접근을 허용한다.
- 제어 장치는 비독점 모드로 생성한다. DLL은 정책·이벤트용 핸들과 서명 전용
  핸들을 각각 열며, 서명 요청은 OVERLAPPED I/O로 대기한다.
- 서명 대기 중에는 DLL 공용 잠금을 유지하지 않는다. 종료 이벤트가 발생하면
  요청을 취소하고 완료를 확인한 뒤 스레드와 장치 핸들을 정리한다.
- 커널은 취소 콜백과 파일 객체별 CLEANUP에서 대기 IRP를 한 번만 완료한다.
- 관리자 클라이언트의 추가 핸들은 허용하지만 서명 대기 슬롯은 하나이다.
- 정책 명령, 상태 조회 및 이벤트 일괄 수신은 `METHOD_BUFFERED` IOCTL을 사용한다.
- 정책 변경 IOCTL은 읽기·쓰기 장치 접근을 모두 요구하고 상태·이벤트 조회 IOCTL은
  읽기 접근을 요구한다.
- 서명 질의 대기(`UF_PROC_IOCTL_WAIT_SIGNATURE`)는 읽기 접근을, 서명 결과 응답
  (`UF_PROC_IOCTL_COMPLETE_SIGNATURE`)은 읽기·쓰기 접근을 요구한다.
- DLL 또는 UI 연결이 끊겨도 이미 적용된 정책은 유지한다.

### 10.2 정책 명령

`IOCTL_UF_PROC_REPLACE_POLICY`는 `UF_PROC_REPLACE_POLICY` 전체를 검증한 뒤 프로세스
정책 리스트를 원자적으로 교체한다.

- 정책은 최대 `UF_PROC_MAX_POLICIES`개이다.
- `ProcessName`은 필수이며 중복 정책의 식별 키로만 사용한다.
- `ProcessPath`는 선택 문자열이고 `IsCmpFullPath`가 1 이상이면 필수이다.
- `IsCmpFullPath`가 켜진 정책은 커널이 얻은 전체 경로와 일치해야 실행을 허용한다.
  커널이 전체 경로를 얻지 못하거나 일치하지 않으면 차단한다.
- `IsSign`이 1 이상이면 사용자 모드 서명 확인 응답이 필요하다. 사용자 모드
  클라이언트가 없거나 응답이 timeout이면 차단한다.
- 문자열 길이는 종결 문자를 제외한 문자 수이며 남는 배열 영역은 0이어야 한다.
- 중복 `ProcessName`은 요청 내 마지막 정책을 기준으로 처리한다.
- 정책과 일치하지 않는 프로세스는 기본적으로 허용하되, 일치 정책의 조건을 통과한
  실행만 커널 내부 `ProcList`에 기록한다.

`IOCTL_UF_PROC_ADD_POLICY`는 기존 정책에 하나 이상의 정책을 추가한다. 같은
`ProcessName`이 있으면 기존 정책을 삭제하고 새 정책으로 교체하며 실행 중인 노드는
새 정책의 `ProcList`로 이동한다.

`IOCTL_UF_PROC_REMOVE_POLICY`는 하나 이상의 `ProcessName`을 받아 일치하는 정책과
그 정책의 실행 노드를 삭제한다.

`IOCTL_UF_PROC_CLEAR_POLICY`는 모든 정책과 실행 추적 노드를 초기화한다.
`IOCTL_UF_PROC_QUERY_STATE`는 정책 세대, 정책 수, 이벤트 큐 깊이, 누적 유실 수와
클라이언트 연결 상태를 `UF_PROC_STATE_REPLY`로 반환한다. 정책 교체와 초기화 때마다
드라이버가 정책 세대를 증가시킨다.

### 10.3 생성 차단과 안전 규칙

- `PsSetCreateProcessNotifyRoutineEx` 콜백은 프로세스 이름, 전체 경로 및 `IsSign`을
  정책에 따라 평가한다.
- 일치 정책의 조건을 통과하면 프로세스 핸들·PID·경로·정책 포인터를 커널 `ProcList`
  마지막에 추가한다. 프로세스 종료 통지에서 해당 노드를 제거한다.
- `IsCmpFullPath` 정책에서 정확한 이미지 경로를 얻지 못하면 차단한다.
- `IsSign` 정책은 `IOCTL_UF_PROC_WAIT_SIGNATURE`로 사용자 모드에 전체 경로 질의를
  전달하고 `IOCTL_UF_PROC_COMPLETE_SIGNATURE` 응답을 동기적으로 기다린다. 기본
  제한 시간은 `UF_PROC_SIGNATURE_TIMEOUT_MS`이며 timeout과 연결 부재는 차단이다.
- `Set`으로 전체 정책을 교체할 때 이미 실행 중인 `ProcList` 노드는 삭제하지 않고
  동일 `ProcessName`의 새 정책에 재연결한다. 새 정책에 이름이 없으면 보류 목록에
  유지한다.
- 보호 프로세스와 보호 프로세스 라이트는 차단하지 않는다.
- `smss.exe`, `csrss.exe`, `wininit.exe`, `services.exe`, `lsass.exe`, `winlogon.exe`,
  `system`은 정책 등록 단계와 커널 경계에서 모두 거부한다.

### 10.4 프로세스 이벤트

드라이버는 고정 크기 비페이징 링 큐에 `UF_PROC_EVENT`를 기록하고
`IOCTL_UF_PROC_DEQUEUE_EVENTS`로 최대 `UF_PROC_MAX_EVENT_BATCH`개를 한 번에 반환한다.

- `UfProcEventCreate`: PID, 부모 PID, 이미지 경로, 허용·차단 결과와 규칙 ID
- `UfProcEventExit`: 종료 PID
- `UfProcEventAccess`: 요청자 PID, 대상 PID, 핸들 생성·복제 종류와 접근 마스크
- 모든 이벤트: 단조 증가 시퀀스, UTC 시스템 시각과 정책 세대

WPF 프로세스 로그는 현재 UI 연결에서 정책 적용이 성공한 이후부터 표시한다.
성공한 요청의 규칙 ID·프로세스명 목록과 적용 완료 시각을 별도 저장하며, 추가·편집만
한 규칙은 표시 대상에 포함하지 않는다. 이전 커널 정책이 남아 있어도 현재 연결에서
적용 전이면 표시하지 않는다. 성공한 정책 교체·초기화 및 연결 해제 때 기존 화면과
대기 큐를 비운다. 적용 실패는 직전 성공한 표시 기준을 유지하고 재연결 후에는 다시
적용해야 한다. 적용 완료 전에 생성된 이벤트는 늦게 수신돼도 제외한다.

이 기준을 통과한 생성 이벤트 중 `RuleId != 0`인 항목만 표시한다. 이 값은 커널이
실행 당시 적용 정책의 프로세스명과 일치하면 경로·서명 검사 전에 설정하므로,
같은 이름의 경로 불일치·서명 실패 차단도 표시 대상이다. 생성 이벤트의 `UfProcActionObserved`는
해당 드라이버 정책을 통과한 것으로 표시하며 다른 구성 요소까지 포함한 실행 성공을
보장하는 뜻은 아니다. 커널 이벤트 수집과 DLL 전달 및 공개 ABI는 변경하지 않는다.

콜백은 큐가 가득 차도 기다리지 않고 새 이벤트를 버린 뒤 누적 유실 수를 증가시킨다.
클라이언트가 없을 때는 이벤트를 큐에 넣지 않는다. 이 규칙으로 프로세스 생성과 핸들
접근 경로가 사용자 모드 속도나 연결 상태에 종속되지 않게 한다.

### 10.5 `uf_procwarp` 공개 C ABI

- `UfProcInitialize`, `UfProcShutdown`: DLL 수명 주기
- `UfProcConnect`, `UfProcDisconnect`, `UfProcIsConnected`: 제어 장치 연결
- `UfProcReplacePolicy`, `UfProcReplacePolicyV2`, `UfProcAddPolicyV2`,
  `UfProcRemovePolicyNames`, `UfProcClearPolicy`, `UfProcQueryState`: 정책과 상태 관리
- `UfProcStartEventReceiver`, `UfProcStopEventReceiver`: 제한된 큐를 폴링하는 이벤트 콜백
- `UfProcGetErrorMessage`: Win32 오류 메시지 변환

`UF_PROC_POLICY_INPUT`의 규칙 배열과 문자열은 호출 중에만 유효하면 된다. DLL은 이를
고정 크기 드라이버 메시지로 복사한다. 이벤트 콜백의 `UF_PROC_EVENT` 포인터도 콜백
실행 중에만 유효하다.

### 10.6 오류와 호환성

- 버전 불일치: `STATUS_REVISION_MISMATCH`
- 구조체 또는 버퍼 크기 불일치: `STATUS_INFO_LENGTH_MISMATCH` 또는
  `STATUS_BUFFER_TOO_SMALL`
- 규칙 수·문자열·비교 방식·중복·필수 이미지 오류: `STATUS_INVALID_PARAMETER`
- 지원하지 않는 명령: `STATUS_INVALID_DEVICE_REQUEST`
- 서명 대기 슬롯 중복 요청: `STATUS_DEVICE_BUSY`

이번 수정은 장치 연결·취소 처리 변경이며 공개 구조체와 IOCTL 번호는 바뀌지 않는다.
V2 ABI를 유지하며 진단 드라이버 버전 3으로 수정된 SYS를 식별한다.
새 DLL은 수신 시작 전 진단 버전을 조회하고 취소 처리가 없는 구버전 SYS에는
`ERROR_REVISION_MISMATCH`를 반환한다. SYS와 DLL을 함께 교체해야 한다.

드라이버와 DLL은 같은 V2 구조체 크기와 필드 배치를 사용해야 하며 알 수 없는 상위
버전을 하위 버전으로 해석하지 않는다.

## 11. 이전 별도 디스크 드라이버 규약 V1 (현행 배포에서 제외)

2026-09-14 사용자 요청으로 아래 별도 디스크 드라이버와 DLL은 솔루션 빌드 및 UI
배포에서 제외한다. 아래 내용은 이전 시험 구현의 기록이며 현행 제어 경로가 아니다.
현행 파일 미니필터 이관 규약은 12절을 따른다.

2026-09-14 구현 계약: `UF_BootProtectionFactory/include/uf_boot_protocol.h`가
V1 고정 크기 ABI의 기준이다. `\\.\UF_BootProtectionFactory`를 관리자/SYSTEM만
열 수 있으며 QUERY(0x930), SET(0x931), EVENTS(0x932) METHOD_BUFFERED IOCTL을 쓴다.
SET은 읽기·쓰기를 요구한다. 최대 장치 32, 보호 구간 64, 이벤트 일괄 32개다.
구조체는 pack(8), 버전·크기·장치 부착 ID·예상 정책 세대를 검증한다.
시작은 장치 배치를 검증한 뒤 보호 상태를 원자적으로 활성화한다. 정지는 해당 장치의
차단만 해제한다. 통신 연결·UI 종료로 보호 상태를 바꾸지 않는다. 재부팅·장치 재부착은
새 ID와 정지 상태로 시작한다. 초기 지원은 별도 데이터 VHDX이며 OS 디스크는 제외한다.
이벤트는 원시 IRP의 PID·생성 시각과 조회 가능한 경로를 기록하며 정보 부족을 표시한다.
상태 조회와 이벤트 수신은 블로킹 폴링이 아닌 즉시 응답이고, 시작 배치 검사는 별도 실행한다.
기존 파일/프로세스 ABI에는 변경이 없다. 유지보수 허용과 자동 종료·격리는 후속 단계다.

| 형식 | 바이트 | 핵심 필드 |
| --- | ---: | --- |
| `UF_BOOT_HEADER` | 8 | Version, Size |
| `UF_BOOT_RANGE` | 24 | 64비트 Offset, Length, Kind |
| `UF_BOOT_DEVICE_INFO` | 2000 | DeviceId, PolicyGeneration, DiskBytes, BlockedWrites, 상태·영역 |
| `UF_BOOT_DEVICE_LIST` | 64016 | Count와 장치 32개 |
| `UF_BOOT_SET_REQUEST` | 32 | DeviceId, ExpectedGeneration, Enabled, Reserved=0 |
| `UF_BOOT_EVENT` | 1136 | Sequence, Time, 장치·정책·PID·생성 시각, 쓰기 범위, PathStatus, Path |
| `UF_BOOT_EVENT_BATCH` | 36376 | Count, Dropped, 이벤트 32개 |

QUERY/EVENTS 입력은 `{Version=1, Size=8}` 공통 헤더이며 출력은 각각 전체
DEVICE_LIST/EVENT_BATCH다. SET 입력은 32바이트, 출력은 2000바이트 DEVICE_INFO다.
부분 크기나 다른 버전은 오류이며 DLL도 반환 바이트 수·버전·크기·개수·문자열을 검사한다.
장치 상태는 STOPPED=0, SCANNING=1, ACTIVE=2, UNSUPPORTED=3, FAILED=4, REMOVED=5다.
LAB_DISK=1, READY=2 플래그와 실제 상태를 함께 해석한다. 장치 이름은 표시 정보이며
SET 대상은 현재 조회한 DeviceId/PolicyGeneration으로 지정한다.

- `UfBootQueryDevices`, `UfBootSetProtection`, `UfBootReadEvents`는 DWORD Win32 오류를
  반환한다. 각 호출은 독립 핸들을 사용하고 SET은 10초, 조회는 3초 내에 사용자 모드로
  돌아온다. 시간 초과는 보호 해제를 의미하지 않으므로 상태를 다시 조회해야 한다.
- 이벤트는 전역 유한 큐에서 읽은 만큼 소비한다. 초기 V1은 단일 UI 소비자용이며,
  여러 클라이언트 간 방송·재전송·세션 영속성은 제공하지 않는다. 별도의 자동 조치는 없다.
- 커널 NTSTATUS와 DLL GetLastError를 구분한다. 경로 미확인은 빈 Path와 PathStatus로
  표시한다. UI 보완 경로는 같은 프로세스 핸들의 생성 시각 일치가 확인된 경우에만 쓰고
  출처를 구분한다. PID나 경로만으로 종료·삭제하지 않는다.
- UI가 없어도 차단과 큐 유지는 계속한다. 큐 포화는 누적 Dropped를 증가시키며 쓰기를
  통과시키지 않는다. 요청 처리 중 사용자 모드나 디스크 기반 이미지 경로 조회를 기다리지 않는다.
- 초기 V1은 [설계안](부팅영역보호_설계안.md)의 전체 목표보다 좁다. 유지보수 허용,
  부팅 세션 영속성, 이미지 파일 신원 및 종료·격리 결과는 후속 버전에서 정의한다.

## 12. MetisD 선두 영역 보호의 파일 미니필터 이관

기존 파일 V2 메시지와 이벤트 구조체 배치는 변경하지 않고 명령 및 Action을 추가한다.
기존 폴더 정책 ABI는 그대로 유지하며, 구버전 드라이버는 새 명령을 지원하지 않는다는
오류를 반환한다. UI는 이를 보호 정지 또는 성공으로 오인하지 않는다.

- `UfCommandSetBootProtection=5`: `UF_SET_BOOT_PROTECTION` 24바이트. 기존 16바이트
  `UF_MESSAGE_HEADER` 다음에 `Enabled`(ULONG, 0/1), `Reserved`(ULONG, 0)를 둔다.
- `UfCommandQueryBootProtection=6`: 입력은 기존 16바이트 헤더이며 출력은
  `UF_BOOT_PROTECTION_STATE` 40바이트이다. ULONG `Version`, `Size`, `Enabled`,
  `ProtectedBytes` 다음에 ULONGLONG `InspectedWrites`, `BlockedWrites`,
  `InspectionFailures`를 둔다. Version은 파일 규약 2, ProtectedBytes는 2048이다.
- 헤더 및 본문의 예약 필드, 정확한 입력 크기, 출력 크기를 검증한다. SET은 출력이
  없고 성공 뒤 QUERY로 실제 상태를 다시 확인한다.
- 공개 C ABI는 `DWORD __stdcall UfFltSetBootProtection(BOOL Enabled)` 및
  `DWORD __stdcall UfFltQueryBootProtection(UF_BOOT_PROTECTION_STATE* State)`이다.
  기존 `uf_fltwarp.dll`의 연결과 제한 시간 요청 경로를 이용한다.
- `UfEventBootDenied=5`, `UfEventBootInspectionFailed=6`을 `UF_FILE_EVENT_V2.Action`에
  추가한다. 기존 필드를 재해석하지 않는다. Path는 대상 장치·볼륨, Image와 ProcessId,
  ProcessCreateTime은 요청 프로세스 식별 정보이며 Operation은 Write이다.
- 실패 이벤트는 차단을 뜻하지 않는다. 원본과 같이 비교 불가 시 통과하며 누적 실패를
  상태와 로그에 노출한다. 알림 수신 실패가 이미 결정한 차단을 취소하지 않는다.
- 기본은 정지이다. 파일 포트 연결만으로 시작하지 않는다. 명시적 시작·정지와 언로드만
  활성 상태를 바꾼다. UI 연결 해제와 폴더 정책 교체·초기화는 보호 상태를 바꾸지 않는다.
- 이관 범위는 원본처럼 콜백에 전달된 원시 디스크·볼륨 선두 2048바이트의 변경 비교이다.
  VHDX 전용 조건이나 디스크 선택은 없다. 전체 GPT 엔트리·백업 GPT 보호 또는 모든
  물리 디스크 직접 I/O 수신을 보장하는 새 구현으로 표시하지 않는다.
- 원본의 제품 전용 신뢰 프로그램 목록을 일반 폴더 허용 목록으로 대체하지 않는다.
  커널·페이징 I/O 및 시스템/관리 클라이언트 예외와 안전 보완 사항은 이관 문서에 기록한다.
- 별도 디스크 탭 대신 파일 제어 탭에서 시작·정지·실제 상태·실패 수를 표시하며,
  차단·검사 실패는 기존 파일 이벤트 목록에 프로세스 이미지 경로와 함께 표시한다.
