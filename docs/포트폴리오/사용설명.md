# 파일 제어와 프로세스 제어 사용 설명

2026-09-10 사용자 제공 Windows 11 Hyper-V VM 실행 캡처와 현재 구현 기준이다.

## 1. 공통 연결과 적용 순서

1. 복구 가능한 시험용 VM에서 UI를 관리자 권한으로 실행한다.
2. 해당 드라이버를 설치하고 연결한다. 이미 설치했다면 연결 버튼으로 로드·연결한다.
3. 상단에서 파일 필터와 프로세스 제어 필터의 연결 상태를 각각 확인한다.
4. 원하는 탭에서 정책을 편집한 뒤 `정책 적용`을 누른다.
5. 정책 적용 완료 문구를 확인한 다음 파일 접근 또는 프로세스 실행을 시험한다.

상단 초록색 표시는 통신 연결 상태다. 정책 적용 완료를 의미하지 않는다.
목록 추가·편집·선택 제거는 적용 전까지 드라이버에 반영하지 않는다.
연결 해제는 통신을 닫는 동작이며 드라이버 제거나 정책 초기화와 다르다.
서명 확인을 요구하는 프로세스 정책이 남아 있으면 클라이언트 연결 해제 후
서명 질의에 응답할 수 없어 해당 이름의 이후 실행을 차단할 수 있다.

## 2. 파일 제어 버튼과 옵션

| 위치 / 항목 | 기능 |
| --- | --- |
| 상단 파일 필터 연결 | 설치된 드라이버를 로드하고 통신·이벤트 수신을 시작한다. |
| 상단 파일 필터 연결 해제 | 파일 이벤트 수신을 중지하고 통신을 닫는다. |
| 감시 폴더 / 폴더 추가 | 접근을 관찰할 폴더를 편집 목록에 추가한다. |
| 감시 폴더 / 숨김 폴더 생성 | 선택한 부모 경로에 고정된 6자리 식별자 `!D4E91A`를 만들고 `Hidden` 속성을 적용한 뒤 감시 목록에 추가한다. |
| 감시 폴더 / 선택 제거 | 선택한 감시 폴더를 편집 목록에서 제거한다. |
| 보호 폴더 / 폴더 추가 | 접근을 제한할 폴더를 편집 목록에 추가한다. |
| 보호 폴더 / 숨김 폴더 생성 | 선택한 부모 경로에 고정된 6자리 식별자 `!D4E91A`를 만들고 `Hidden` 속성을 적용한 뒤 보호 목록에 추가한다. |
| 보호 폴더 / 선택 제거 | 선택한 보호 폴더와 연결된 허용 프로그램 목록을 편집 대상에서 제거한다. |
| 프로그램 추가 | 선택한 보호 폴더에 접근할 수 있는 실행 파일을 추가한다. |
| 프로그램 영역 / 선택 제거 | 선택한 허용 프로그램을 해당 폴더의 목록에서 제거한다. |
| 읽기 / 쓰기 | 프로그램별 접근 권한이다. 둘 다 끈 허용 규칙은 적용할 수 없다. |
| 코드 서명 | 허용 프로그램에 서명 신뢰 확인을 요구한다. |
| 전체 경로 / 프로세스 이름 | 허용 프로그램을 전체 경로로 비교할지 파일 이름으로 비교할지 선택한다. |
| 파일 필터 설치 | 설치·로드 후 통신 연결을 시도한다. |
| 파일 필터 제거 | 정책 초기화를 시도한 후 연결을 닫고 드라이버 제거를 요청한다. |
| 미끼 폴더 생성 | 모든 고정 로컬 드라이브의 루트(1단계)와 루트 바로 아래 기존 폴더(2단계), 문서·음악·동영상·다운로드에 `!D4E91A`를 만들고 `Hidden` 속성을 적용한다. 랜섬웨어 접근·변경 감지를 위한 미끼 경로로 사용한다. |
| 정책 적용 | 현재 감시·보호 목록 전체를 드라이버 정책으로 전송한다. |
| 정책 초기화 | 적용한 드라이버 정책을 비운다. UI 편집 목록은 유지한다. |
| 로그 지우기 | 화면 로그만 지운다. 드라이버 정책은 유지한다. |

감시 정책은 접근을 관찰하며 자체적으로 차단하지 않는다. 보호 정책은 해당 폴더의
허용 규칙과 권한·서명 조건에 맞는지를 판단한다. 이름 비교는 같은 이름의 다른 위치
실행 파일도 후보로 삼으므로 전체 경로 비교와 보안상 의미가 다르다.

### 캡처의 파일 정책과 로그

감시 `C:\MonitorDir` 1개, 보호 `C:\ProtectDir` 1개를 적용했다.
보호 폴더의 허용 프로그램으로 `C:\Windows\notepad.exe`를 선택했으며,
읽기·쓰기를 켜고 서명 확인을 껐다. 비교 방식은 `프로세스 이름`이다.

| 로그 열 | 의미 |
| --- | --- |
| 시각 | UI가 이벤트를 받은 현지 시간 |
| 구분 | `차단`: 접근 거부. `감시`: 관찰 이벤트 또는 보호 폴더의 허용 접근 |
| PID | 접근 요청 프로세스 식별자 |
| 프로세스 | 접근 주체의 이미지 경로 |
| 파일 경로 | 접근 대상의 커널 형식 경로 |

캡처 맨 위 데이터 행부터 다음과 같이 읽는다. 날짜는 모두 2026-09-10이다.

| 행 | 시각 | PID | 결과 / 설명 |
| --- | --- | --- | --- |
| 1~3 | 02:54:59.835 | 6204 | 보호 폴더 또는 `sdfsdf.txt` 접근 차단 |
| 4~5 | 02:54:59.832 | 6204 | 보호 폴더 또는 `sdfsdf.txt` 접근 차단 |
| 6 | 02:54:59.818 | 6204 | `sdfsdf.txt` 접근 차단 |
| 7~10 | 02:54:59.817 | 6364 | 보호 폴더 접근 감시 |
| 11~13 | 02:54:58.507 | 6364 | 보호 폴더 접근 감시 |
| 14~15 | 02:54:56.103 | 6364 | 보호 폴더 접근 감시. 마지막 행은 하단 일부가 잘림 |

한 번의 사용자 동작도 여러 파일 I/O를 발생시킬 수 있다. 로그 행 수를 사용자 동작
횟수나 차단한 프로그램 수로 해석하지 않는다. PID 6204의 전체 실행 경로는 화면에서
잘렸으므로 프로그램 이름을 확정하지 않는다. 이 캡처에는 `MonitorDir` 접근 행이 없다.

## 3. 프로세스 제어 버튼과 옵션

| 항목 | 기능 |
| --- | --- |
| 전체 경로 추가 | 파일 이름과 전체 경로를 저장하고 경로 일치를 실행 조건으로 사용한다. |
| 파일 이름 추가 | 파일 이름으로 정책을 찾는다. 같은 이름의 기존 규칙은 새 규칙으로 교체한다. |
| 선택 제거 | 선택한 규칙을 편집 목록에서 제거한다. 반영하려면 정책 적용이 필요하다. |
| 규칙 ID | 정책 규칙의 식별 값 |
| 비교 방식 / 실행 파일 | 이름 비교 또는 경로 비교 방식과 대상을 표시한다. |
| 코드 서명 필요 | 사용자 모드 서명 검증을 요구한다. 검증 실패·클라이언트 없음·시간 초과 시 차단한다. |
| 정책 적용 | 현재 목록으로 드라이버 정책을 교체하고 성공한 정책을 UI 로그 표시 기준으로 저장한다. |
| 정책 초기화 | 드라이버 정책과 UI의 로그 표시 기준·기존 로그를 비운다. 편집 목록은 유지한다. |
| 프로세스 제어 필터 설치 | 드라이버 설치·로드 후 통신·이벤트 수신까지 확인한다. |
| 프로세스 필터 로드·연결 | 설치한 드라이버를 로드하고 통신·수신을 시작한다. 상단 버튼과 동일하다. |
| 프로세스 필터 연결 해제 | 통신을 닫고 현재 UI 로그 표시 기준과 로그를 초기화한다. 상단 버튼과 동일하다. |
| 프로세스 제어 필터 제거 | 정책 초기화를 시도한 뒤 연결을 닫고 제거를 요청한다. |
| 로그 지우기 | 표시 목록과 대기 로그만 비운다. 정책은 유지하며 이후 실행은 다시 기록한다. |

현재 UI 연결에서 `정책 적용`에 성공한 규칙의 이름과 ID에 해당하며 적용 완료
이후에 생성한 이벤트만 표시한다. 미적용 편집 내용이나 이전 연결의 커널 정책만으로
표시를 시작하지 않는다. 미등록 실행·종료·다른 프로세스 접근 이벤트는 이 UI 목록에서
제외한다. 이는 UI 표시 조건이며, 커널의 접근 감시 기능 제거를 의미하지 않는다.

### 캡처의 프로세스 정책과 로그

규칙 ID 1, 파일 이름 `notepad.exe`, 코드 서명 필요 옵션으로 정책 1개를 적용했다.
로그 열은 시각, 프로세스명, 실행 결과, PID, 실행 파일 경로다. 시각은 커널이 기록한
생성 이벤트 시간을 현지 시간으로 변환한 값이다. `통과`는 실행 허용, `차단`은 생성 거부다.

| 행 | 시각 | PID | 결과 |
| --- | --- | --- | --- |
| 1 | 2026-09-10 02:54:34.096 | 6364 | Notepad.exe 통과. 파일 로그의 PID 6364와 대조 가능 |
| 2 | 2026-09-10 02:54:34.001 | 9328 | Notepad.exe 통과. 첫 행과 별도 실행 인스턴스 |
| 3 | 2026-09-10 02:51:23.829 | 10780 | Notepad.exe 통과. 위 두 행보다 이전 실행 |

## 4. 확인 범위

사용자는 파일·프로세스 기능의 정상 동작을 확인하고 실행 화면을 제공했다.
문서는 해당 화면에서 확인할 수 있는 내용과 소스의 기능 설명을 구분한다.
프로세스 차단, 서명 시간 초과, 정책 미적용·재연결 상태, 모든 파일 I/O 종류의 차단을
이 두 장의 캡처만으로 입증하지 않는다. 잘린 경로와 화면 밖 로그도 임의로 복원하지 않는다.

PPT에는 전체 화면과 영역별 확대 화면, 모든 버튼·옵션의 설명 및 로그 해설을 담았다.
설명 텍스트는 편집할 수 있으며 원본 캡처는 변경하지 않고 별도로 보관한다.
