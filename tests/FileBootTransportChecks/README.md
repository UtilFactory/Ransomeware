# 파일 부트 보호 전송 모의 시험

드라이버가 없는 개발 장비에서 DLL의 실제 부트 보호 요청 및 오류 로깅 경로를 검사한다.
`uf_fltwarp.c`를 시험 실행 파일에 포함하고 `FilterSendMessage`만 메모리 모의 함수로 교체한다.
포트에는 일반 이벤트 핸들을 사용하므로 실제 핸들 복제·작업 스레드·완료 대기 경로도 실행한다.

## 실행

```powershell
powershell -NoProfile -File .\tests\FileBootTransportChecks\run.ps1
```

기본 MSVC 경로가 다르면 `-VcVars`로 `vcvars64.bat` 경로를 지정한다.
결과물은 `artifacts\file-boot-transport-checks`에 생성한다. 솔루션이나 배포 대상에는 추가하지 않는다.
스크립트 실행이 서명 정책으로 제한된 환경에서는 정책을 변경하지 않고, 승인된 개발자 명령
프롬프트에서 `run.ps1`에 명시된 `cl` 빌드 명령을 직접 실행할 수 있다. 이 저장소의 최종
검증은 해당 방식으로 컴파일·실행했다.

## 검사 범위

- SET 24바이트, QUERY 입력 16바이트·출력 40바이트 및 각 헤더·예약 필드
- `0x80070001`의 반환 코드 1 변환과 원본 HRESULT 로그 보존
- 마지막 오류 스냅숏과 실제 HRESULT 판정의 구분
- 요청 진입·반환·완료 단계 로그와 성공 응답 값 보존
- 짧은 응답, 버전·크기·활성 값·보호 범위 오류 및 실패 시 공개 출력 초기화
- 잘못된 입력과 미연결 요청 거절, 실패 요청 자동 재시도 없음
- Win32 범주가 아닌 HRESULT 값의 보존

2026-09-14 로컬 실행 결과: 경고를 오류로 처리하는 `/W4 /WX` 빌드 성공, 41개 검사 통과.
이 시험은 관리자 권한, 드라이버 연결·설치, 서비스 변경 또는 원시 디스크 입출력을 사용하지 않는다.
커널의 명령 수신이나 실제 부트 쓰기 차단을 검증한 결과로 해석하지 않는다.
